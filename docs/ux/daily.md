# UX 规格：每日挑战（补写，以现有实现为准）

状态：**已实现（`src/ui/daily_page.gd`），补写规格，待用户确认**。玩法见 `docs/01` §5.11。

## 玩家目标

点一下开始今天的挑战。

## 主次层级

- 主行动：底部大按钮（480×110）：「开始挑战」（绿，脉动）/ 失败后「再试一次」两个（广告紫、金币绿，各 310×110）/「今日已完成」（蓝，禁用）。
- 次行动：左上「返回」（150×70）。
- 信息：宝箱大图、连续过关进度、每日宝箱里有什么。

## 布局（750×1334）

```
[返回]                                  y 24（主页的子页面，不是页签）
标题「每日挑战」                         y 18
        [宝箱 250，背后光晕 460]         中线 y = 屏高 27%
   连续过关 N/7 天                       中线 +150
   [格][格][格][格][格][格][宝箱格]      7 格，每格 62，间距 18
┌ 每日宝箱 ───────────────────┐         中线 +300，宽 670，高 176
│ [金币 500][技能×1 ×4][卡 ×1] │
└─────────────────────────────┘
        一行小字（今日免费 1 次 / 明天再来）   按钮上方 46
   [          开始挑战          ]        y = 屏高 − 150
```

- 底部按钮在下半屏拇指区。
- 本页不显示顶栏（金币、生命），与抽奖、排行同属主页子页面。

## 状态

| 状态 | 表现 |
|---|---|
| 今天没打过 | 宝箱关着并上下浮动；「开始挑战」绿色脉动；上方「今日免费 1 次」 |
| 打过但没过关 | 免费次用掉：两个按钮「再试一次」（看广告，紫，没广告时禁用）和（300 金币，绿）；金币不够弹「金币不足」 |
| 今天已过关 | 宝箱打开、不浮动；蓝色禁用按钮「今日已完成」；上方「明天再来」 |
| 连续天数 | 过了的格子亮并弹出星星，没到的灰；最后一格是宝箱 |
| 未开放（第 20 关前） | 不进本页，显示锁页（带返回键）和大奖预览 |

## 交互

- 开始 / 再试：进入当天挑战关（`App.go_daily`），免费一次不扣生命，看广告或付金币再进不扣生命。
- 局内过关 → 开每日宝箱的开奖弹窗（标题「每日宝箱」；连续满 7 天标题是「七日大宝箱」），奖品含一张收藏卡时先翻卡再开奖；收下后回每日挑战页。
- 返回 → 主页。

## 动效

- 进场：宝箱弹出；连续天数格子的星星依次弹出。
- 常驻：未完成时宝箱上下浮动；「开始挑战」脉动。同屏常驻动效只有这两处。
- 点击：按钮标准按下缩放。

## 文案

| 键 | 中文 | English |

| UI_TAB_DAILY | 每日挑战 | Daily |

| DAILY_RETRY | 再试一次 | Try again |

## 参考结论

每日关的共同做法：入口在主页、每天一次的仪式感、连续天数奖励、失败可付费或看广告再来。取「连续天数 + 大宝箱」结构；不取具体的日历样式。

## 验收点

1. 三秒内看出今天能不能打、打一下是否免费。
2. 免费次用完后，两种再试方式并排、价格清楚。
3. 打过的当天按钮是禁用的，不会重复进入。
4. 连续天数断了会清零，格子表现同步。
5. 每个状态的按钮都不小于 96 高。

## 待确认（实现与 `docs/01` 不一致或文档没写）

1. **七日大宝箱的内容**（3000 金币 + 每种技能 2 个 + 1 小时无限生命）页面上没有写，最后一格只是个宝箱图。docs/01 §5.11 写了页面要显示「每日宝箱里有什么」，没说大宝箱要不要显示。
2. **「再试一次」两个按钮同名**，靠紫色广告角标和金币价格区分。是否要加区分文字？
3. 每日宝箱里的卡，页面只写「×1」和鱼缸图标，没说「优先给没有的」。
4. 没有倒计时（距明天还有多久），docs/01 也没要求。
5. 「不扣生命、不算进度、不记连败」是局内逻辑，本页没提示玩家，是否要在页面写一行说明？
6. docs/01 §5.3 把每日挑战列为「主页入口」，实现一致（主页右侧入口 → 子页面）；`home_screen.gd` 里仍保留 `TAB_DAILY` 常量，属于实现细节，不影响玩家。
