# 02 关卡设计

## 1. 难度旋钮

| 旋钮 | 含义 | 影响 |
|---|---|---|
| `species` | 本关鱼种数 | **最主要的难度来源** |
| `orders` | 鱼缸订单数（总鱼数 = 各订单容量之和） | 局越长越容易出错，仅次于鱼种数 |
| `bubbles` / `layers` | 气泡数与层数 | 气泡数 ≈ 总鱼数 ÷ 3（每泡 1–5 条，必须装得下） |
| `slack` | 参考解用到的暂存槽峰值（0–4） | 微调用，影响小于前两项 |
| `hidden` | 迷雾泡占比 | 增加难度 |
| 障碍 | 锁链、限时、冰封等 | 增加难度 |

## 2. 难度曲线

锯齿形：每 5 关一个小高峰（第 5、10、15… 关为**挑战关**，界面有标记、奖励翻倍），高峰后一关明显放松。

| 关卡段 | species | 总鱼数 | bubbles | layers | slack | 新机制 |
|---|---|---|---|---|---|---|
| 1–2 | 3 | 9–18 | 4–6 | 1 | 0 | 引导 |
| 3–11 | 4–5 | 24–36 | 8–12 | 2 | 0–1 | 多层 |
| 12–24 | 5–6 | 45–60 | 15–20 | 2–3 | 1 | 锁链泡 |
| 25–39 | 6 | 54–66 | 18–22 | 3 | 1–2 | 限时缸 |
| 40–59 | 6–7 | 60–75 | 20–25 | 3 | 1–2 | 迷雾泡 |
| 60–79 | 7 | 66–81 | 22–27 | 3 | 1–2 | 冰封泡 |
| 80–109 | 7–8 | 72–90 | 24–30 | 3–4 | 2 | 大鱼缸 |
| 110–200 | 7–8 | 75–96 | 25–32 | 3–4 | 2 | 结伴鱼 |
| 挑战关 | 所在段 +2 | 所在段 ×1.4，最高 144 | 按鱼数 | +1 | +1 | — |
| 201+ | 程序化无限关，参数在 110–200 段内按种子循环 |

### 原型模拟数据（2026-11-15）

用 Python 原型实现了基础规则（分层遮挡、2 个缸、5 格暂存、固定订单队列）和按解构造的生成器，每组参数 300 个种子：

| species | 总鱼数 | bubbles | slack | 参考解可解 | 贪心机器人 2 缸 | 贪心机器人 3 缸 | 随机机器人 2 缸 |
|---|---|---|---|---|---|---|---|
| 3 | 9 | 4 | 0 | 100% | 100% | 100% | 100% |
| 3 | 18 | 6 | 0 | 100% | 100% | 100% | 89% |
| 5 | 36 | 12 | 1 | 100% | 96% | 99% | 1% |
| 6 | 60 | 20 | 1 | 100% | 77% | 94% | 0% |
| 6 | 60 | 20 | 2 | 100% | 62% | 88% | 0% |
| 7 | 75 | 25 | 2 | 100% | 50% | 79% | 0% |
| 8 | 90 | 30 | 2 | 100% | 39% | 68% | 0% |
| 9 | 108 | 36 | 2 | 100% | 28% | 54% | 0% |
| 10 | 120 | 40 | 3 | 100% | 14% | 43% | 0% |
| 12 | 144 | 48 | 4 | 100% | 7% | 31% | 0% |

结论：

- 生成器产出的关卡全部可解，暂存峰值与 `slack` 一致。
- 第 1 关乱点也能过，符合「不可能失败」的引导要求。
- 难度主要由鱼种数和总鱼数决定；多开一个缸位的帮助很大（广告缸位有真实价值）。
- 10 种以上、120 条以上的关卡对「只顾眼前」的打法通过率很低，所以普通关压在 7–8 种、96 条以内，大关只用于挑战关。

贪心机器人只会「有目标鱼就点，否则点最快用得上的」，不会规划拆泡顺序，真人会更好。上表的关卡段参数按贪心机器人定：普通关 50–95%，挑战关 15–40%。**真人通过率要到 M3 有可玩版本后实测再校准**，这是目前最大的未知数。

备用手段：如果实测偏难，把订单队列从「写死」改为「半自适应」（下一个缸优先要暂存槽里或开放气泡里已有的鱼种），可以大幅降低难度而不改关卡数据。

### 动态难度

- 同一关连续失败 2 次：下次进入换成更易的变体（鱼种数 −1）。
- 连续失败 4 次：再降一档，并免费送 3 号缸位。
- 每关预生成 3 个变体（普通 / 易 / 更易）。

## 3. 关卡数据格式

`config/levels/level_0023.json`

```jsonc
{
  "id": 23,
  "seed": 918273,
  "challenge": false,
  "buffer": 5,
  "bowlSlots": 2,                 // 默认开启的缸位数
  "palette": 6,                   // 用到的鱼种槽位数 0..5，运行时映射到具体鱼种
  "orders": [                     // 订单队列，顺序即出场顺序
    { "s": 0, "cap": 3 },
    { "s": 3, "cap": 3, "timer": 60 },
    { "s": 1, "cap": 6 }
  ],
  "bubbles": [
    {
      "id": 0, "x": 0.22, "y": 0.31, "r": 0.16,   // 归一化到气泡场宽度
      "layer": 2,
      "fish": [0, 0, 3, 1],                        // 鱼种槽位
      "under": [4, 7],                             // 被本泡压住的气泡 id
      "chain": 0,                                  // 锁链数字，0 = 无
      "fog": false,
      "ice": [],                                   // 解冻依赖的邻居 id，空 = 不冰封
      "pairs": []                                  // 结伴鱼在 fish 数组中的下标对
    }
  ],
  "variants": ["level_0023_e1", "level_0023_e2"]
}
```

规则：

- 遮挡关系用显式的 `under` 列表，不在运行时做几何判断，保证逻辑确定、可测试。生成器按圆重叠面积 > 15% 自动填。
- 鱼种用槽位号。运行时从玩家已解锁的鱼种里挑 `palette` 个映射上去，要求两两属于不同的「辨识组」（见美术规范），避免两种长得像的鱼同场。
- 不变量（校验器强制）：每个槽位的鱼数 = 该槽位所有订单容量之和；每泡 1–5 条鱼；`under` 无环；`layer` 与 `under` 一致；冰封依赖 `ice` 无环且不指向自己；锁链数字之和不超过在它解锁前能完成的订单数。

## 4. 生成器（`tools/level` 与运行时共用 `src/core/gen`）

采用**按解构造**，生成即可解：

1. 按参数定鱼种数、订单数，随机排出订单队列（相邻同时激活的缸不重复鱼种）。
2. 摆气泡：泊松盘采样 + 分层，算出 `under` 关系。
3. 模拟一条参考解：维护「当前开放的鱼位」集合，按订单顺序往鱼位里填当前缸要的鱼；每隔若干步故意填入一条未来才需要的鱼（它会进暂存槽），次数与间隔由 `slack` 控制，并保证暂存峰值恰为 `slack`。
4. 叠加障碍：在不破坏参考解的前提下加锁链数字、冰封依赖、迷雾、限时（限时秒数 = 参考解步数 × 单步时间 × 宽松系数）。
5. 交给校验器。

随机数只用 `src/core/rng` 的可播种 PRNG（自实现 mulberry32，只用整数运算），禁止全局 `randi()` / `randf()`。同种子在命令行工具与各平台运行时必须产出逐字节相同的关卡。

## 5. 校验器与难度评估

`./run.sh level-verify` 对每个关卡文件执行：

| 检查 | 通过条件 |
|---|---|
| 结构不变量 | 第 3 节全部成立 |
| 可解 | 带记忆化的 DFS 求解器在 2 缸位、不用道具下找到解 |
| 贪心机器人 | 「优先点目标鱼，否则点能最快露出目标鱼的」跑 200 局，记录胜率 |
| 随机机器人 | 纯随机合法点击跑 200 局，记录胜率 |
| 难度落点 | 贪心胜率落在该关卡段目标区间（普通关 50–95%，挑战关 15–40%），否则标红要求重生成 |

输出 `tools/level/report.csv`：关卡号、步数、两种胜率、暂存峰值。调难度曲线看这张表，不靠体感。

## 6. 手工关

第 1–30 关在生成结果上手工微调（教学节奏与首日留存最关键），调完仍必须过校验器。其余关卡纯生成。
