# 10 开发底座：一套仓库出三端，做新游戏照着走

用户 2026-11-18：「这个游戏就是开发底座，我们以后都做类似玩法的游戏，流程一样。」这份文档说明：仓库里哪些是底座（换游戏也照用）、哪些是这款游戏自己的、做新游戏从哪几处改起，以及三端怎么打包上架。

## 1. 一个仓库、一个主干

三个平台：**微信小游戏**（中国大陆）、**Google Play** 和 **App Store**（只上海外）。同一套代码、同一个主干，三端各出一个包。**不为平台开分支、不复制工程**；平台差异只放在下面三处：

| 差异放哪 | 是什么 |
|---|---|
| `client/assets/scripts/platform/` | 平台实现：`platformWechat.ts`（微信）、`platformNative.ts`（Android 和 iOS 共用）、`platformDebug.ts`（浏览器试玩、截图）。启动时 `index.ts` 按运行环境挑一个。业务代码只认 `PlatformBase`，按 `hasCapability` 分支，不按平台 id 分支 |
| `client/native/engine/` | 原生工程：Cocos 的模板 + 我们的桥（iOS `ios/game/FsBridge.mm`、Android `android/app/src/com/cocos/game/FsBridge.java`），收脚本发来的 `fs.*` 事件，调广告、震动、分享 |
| `game.json`（仓库根目录） | 这款游戏的身份：名字、版本号、包名、AdMob 应用 ID 和广告位、微信 appid。打包前 `tools/native/apply.mjs` 按它改写构建配置、Info.plist、AndroidManifest、`config/platform.json` |

## 2. 底座和游戏内容的分界

| 底座（换游戏照用，只修 bug、加通用功能） | 这款游戏自己的（做新游戏要换） |
|---|---|
| `platform/`、`client/native/engine/`、`tools/native/`、`tools/store/` | `game.json` |
| `package.sh` 的平台和产物选择菜单 | 玩法规则 `core/rules`、关卡生成 `core/gen`、关卡文件 `config/levels` |
| 界面框架 `ui/`（页面切换、弹窗、适配、安全区、文案 `tr()`） | 各页面 `pages/`、局内 `game/` 的具体画面 |
| 外围系统 `core/meta`（金币、生命、技能、签到、任务、收藏、抽奖、每日挑战、存档） | 数值 `config/economy.json`、`level_curve.json`、`species.json` |
| 机器人和量具 `core/solver`、`tools/level`、`tools/economy`（难度按「普通玩家花几样才过」量，`docs/02` 第 0 节） | 美术 `art/`、`client/assets/resources/` 里的图和声音 |
| 文档的结构（01–10） | 文档的内容、`store/` 的上架文案和图 |

做新的同类游戏（「把东西从容器里取出来、按种类凑满」这一类）时，外围系统、平台、打包、量具都不用重写，主要换玩法规则、关卡生成、美术和数值。

## 3. 做一款新游戏的步骤

1. **复制仓库**成新仓库（不是在这个仓库开分支），改 CLAUDE.md 的游戏名和玩法一句话。
2. **改 `game.json`**：名字（中英）、`codeName`、版本号、iOS 的 Bundle ID 和 Team ID、Android 的包名、微信 appid；广告位先留测试 ID。跑 `./run.sh native-apply`。
3. **换图标**：新图标放 `art/approved/logo/logo_1024.png`，在 Linux 上跑 `./run.sh native-icons`，生成各平台的应用图标、iOS 启动屏、商店图标，提交。
4. **换玩法和内容**：规则、关卡、美术、数值，按 `docs/01`、`docs/02` 的流程（规则先写文档、难度先用量具量、界面先写 `docs/ux` 规格）。
5. **上架素材**：改 `store/listing.md` 的文案和 `store/briefs/posters/` 的出图需求（画面和图上的字），`store/gen.sh` 让 Codex 整张画，逐张检查字，`python3 tools/store/export.py` 导出各尺寸（第 6 节）。
6. **打包**：第 4 节。

## 4. 打包

在装了 Cocos Creator 3.8.8 的 Mac 上运行 `./package.sh`，输入编号并回车。脚本使用当前工作区；微信、iOS 和 Android 在构建前应用 `game.json`。主菜单输入 0 退出，子菜单输入 0 返回。

| 平台编号 | 产物编号 | 产物 |
|---|---|---|
| 1 微信小游戏 | — | 微信开发者工具工程 `client/build/wechatgame`；资源另放 `client/build/wechatgame-remote/remote`，要传到云存储 |
| 2 iOS | 1 | Xcode 工程 `client/build/ios/proj/*.xcodeproj` |
| | 2 | 模拟器 App |
| | 3 | 未签名真机 App |
| | 4 | `client/build/ios/release/*.ipa` |
| 3 Android | 1 | 调试用 APK |
| | 2 | 上架用 AAB |
| | 3 | Gradle 工程 `client/build/android/proj` |
| 4 网页版 | — | `client/build/web-mobile` |

**第一次打包前要准备的**：

- **iOS**：Xcode（Mac 上有 27.2）。Apple 开发者账号在 Xcode → Settings → Accounts 里登录；Team ID 填进 `game.json` 的 `ios.team`。`game.json` 开着广告时，广告 SDK（Google Mobile Ads + UMP）打包时自动下载到 `client/native/engine/ios/sdk/`（不进仓库）；下不下来照样能编，只是没有广告。Xcode 27 要求最低 iOS 15。在模拟器里跑要另外下载 iOS 模拟器运行时（Xcode → Settings → Components）。
- **Android**：Android Studio（带 SDK、NDK、JDK）；Cocos Creator 的偏好设置里填 SDK、NDK 路径。正式包要签名：用 `keytool` 生成一个上传密钥（`.jks`，不进仓库，丢了要找 Google 重置），在 `~/.gradle/gradle.properties` 写 `RELEASE_STORE_FILE`、`RELEASE_STORE_PASSWORD`、`RELEASE_KEY_ALIAS`、`RELEASE_KEY_PASSWORD` 四项。
- **微信**：微信开发者工具；`game.json` 的 `wechat.appid` 换成自己的。资源放在云开发的**静态网站托管**（安装包只能 4 MB，`docs/04` 第 8 节）。没用云存储：免费体验环境改不了云存储的读权限（默认只有创建者能读，游戏下载会 403），静态托管的文件默认所有人可读（2026-11-18 用 tcb 试过）。第一次要：
  1. 小游戏后台开通云开发，**环境 ID** 填进 `game.json` 的 `wechat.cloudEnv`（现在是 `cloud1-d8g4d0pyi6699a102`）。
  2. 静态托管的域名填进 `wechat.remoteUrl`（`tcb hosting detail` 最后一行，现在是 `https://cloud1-d8g4d0pyi6699a102-1535223200.tcloudbaseapp.com/`）。
  3. 小游戏后台 → 开发管理 → 服务器域名，把这个域名加进「downloadFile 合法域名」（开发者工具里预览前也可以先在「详情 → 本地设置」勾「不校验合法域名」）。
  4. 上传：装了云开发命令行（`npm i -g @cloudbase/cli`，`tcb login`）时 `./package.sh` 自动传（`tcb hosting deploy`）；没装就在云开发控制台「静态网站托管」里把 `client/build/wechatgame-remote/remote` 整个文件夹传到根目录。文件名带 MD5，旧文件留着不影响，攒多了可以清。
  - `remoteUrl` 空着时资源留在包里：开发者工具的模拟器能跑，预览和上传会超过 4 MB。试打包量主包大小时可以临时 `WECHAT_REMOTE_URL=https://example.com/ ./package.sh`。只打包、先不上传：`NO_UPLOAD=1 ./package.sh`。
  - 云开发费用见用户 2026-11-18 的问答：个人版每月十几到几十元，超出的下载流量 0.21 元/GB。

**Cocos 3.8.8 + Xcode 27 的几处坑**（2026-11-18 在 Mac 上编通时绕过的，都写在 `client/native/engine/ios/CMakeLists.txt` 和 `package.sh` 里，换引擎或 Xcode 版本时先看这里）：

| 现象 | 原因 | 怎么绕的 |
|---|---|---|
| 部署版本报错 | Xcode 27 最低 iOS 15 | `game.json` 的 `ios.minVersion` 15.0 |
| 引擎编译报 `'is_floating_point' cannot be specialized` | 新 libc++ 不许特化标准库模板，引擎带的 enoki/half.h 这么做了 | 对引擎目标加 `-Wno-invalid-specialization` |
| 链接失败，警告 libwebp.a「not 8-byte aligned」 | Cocos 预编译的 libwebp.a 和新链接器不兼容，Xcode 27 去掉了旧链接器 | 关掉 WebP（`USE_WEBP OFF`，强制写进缓存），打包时用 libtool 重新打包一份给引擎的 `webp` 目标 |
| 模拟器版链接失败 | 同上，x86_64 那部分 | 模拟器版只编 arm64（Apple 芯片的 Mac） |
| 链接报 `__swift_FORCE_LOAD_$_swiftCompatibility51` 找不到 | 广告 SDK 里有 Swift，工程里没有 Swift 文件不会自动链 Swift 运行时；CMake 3.24 又开不了 Swift | 手动加 Swift 库的搜索路径和三个兼容库 |
| 构建后启动图、`CMakeLists.txt` 的工程名被改 | Cocos 构建时按它的模板改写 | 工程名事先写好（`apply.mjs`）；启动图构建完 `git checkout` 换回来 |

## 5. 广告

**总开关**：`game.json` 的 `ads.enabled`。第一版上架是 `false`（用户 2026-11-18：第一版不集成广告和内购），改了要重新打包。`tools/native/apply.mjs` 按它改这几处：

| 开关 | `true` | `false` |
|---|---|---|
| `config/platform.json` 的 `adsEnabled` | 平台层用广告位 | 平台层当没有广告位：`hasCapability('ads')` 为假，看广告的入口全部隐藏（`docs/01` 7.1） |
| iOS `CMakeLists.txt` 的 `FS_ADS` | 链广告 SDK（`./package.sh` 自动下载） | 不下载、不链，桥按没有广告编译，不弹 UMP、ATT |
| iOS `Info.plist`、`InfoPlist.strings` | 有 `GADApplicationIdentifier`、`NSUserTrackingUsageDescription`、`SKAdNetworkItems` | 这几项去掉（没有跟踪授权弹窗却写了说明，审核会问） |
| Android `app/build.gradle` 的 `FS_ADS` | 依赖 AdMob、UMP，编 `app/ads/on/` 的 `FsAds.java` | 不依赖，编 `app/ads/off/` 的空实现 |
| Android `AndroidManifest.xml` 的广告 ID 权限 | 声明 | `tools:node="remove"` 去掉 |

浏览器试玩（`debug` 平台）也跟这个开关走，地址栏加 `?ads=1` / `?ads=0` 临时看另一种版本。

| 平台 | SDK | 广告位 ID 在哪 |
|---|---|---|
| 微信 | 流量主（`wx.createRewardedVideoAd` 等） | `game.json` 的 `ads.wechat`；空着 = 没有广告（开通流量主之前），看广告的入口自动隐藏（`docs/01` 7.1） |
| iOS | Google Mobile Ads + UMP（用户同意）+ ATT（跟踪授权） | `game.json` 的 `ios.admobAppId`（应用 ID）、`ads.ios`（广告位） |
| Android | Google Mobile Ads + UMP | `game.json` 的 `android.admobAppId`、`ads.android` |

现在填的都是 Google 官方的**测试 ID**，打开广告上架前换成自己 AdMob 后台里建的。启动时先弹 UMP 的同意表（只有欧洲等需要的地区会弹），iOS 再弹 ATT 授权（不同意也能玩，只是广告不个性化），然后加载激励视频和插屏。设置里的「隐私选项」（`hasCapability('privacy_options')`）能随时改同意。

## 6. 上架图和文案

| 文件 | 是什么 |
|---|---|
| `store/listing.md` | 三个商店的名称、副标题、关键词、描述（中英） |
| `store/briefs/posters/*.txt` | 每张上架图一份出图需求（画面 × 语言），文字也写在需求里，Codex 整张画出来（用户 2026-11-18：全部用 AI 直接生成，不要自己拼；字要大到手机上看得清，每张只一句短标题） |
| `store/gen.sh` | Codex 出图到 `art/raw/store/posters/`（不进仓库），附我们自己的风格参照图；要重画某张就删掉它再跑 |
| `tools/store/export.py` | 只做等比缩放、裁两边，导出各商店尺寸 → `store/images/` |
| `tools/native/icons.py` | 应用图标、启动屏、商店图标 |

每张图（连同上面的字）都是 AI 一次画出来的，画完要逐张看一遍字有没有写错，写错就删掉重画。`store/images/` 里每种尺寸 5 张：App Store 6.9 英寸（1320×2868）、6.5 英寸（1284×2778），Google Play 手机（1080×1920）和置顶大图（1024×500），微信小游戏详情页（1080×1920，只有中文）；图标 `store/images/icon/`。iOS 只做 iPhone 版，不用交 iPad 截图。
