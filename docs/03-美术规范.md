# 03 美术规范

## 1. 原则：同品类观感，原创设计

参考截图只用来确定**品类气质**：明亮、圆润、高饱和的卡通海洋休闲风，粗描边大字，厚实的立体按钮。

除此之外全部原创，以下内容**不得**出现：

- 照着参考截图画的鱼、鱼缸、木架、头像、道具图标、场景插画、标题字。
- 参考游戏的鱼名、场景名、界面逐像素布局。
- 把参考截图作为图生图的输入喂给 Codex。

原因不只是规矩：微信、Google Play、App Store 都会因美术雷同下架并可能封号，软著和商标也过不了。

## 2. 本作的视觉识别

一句话：圆润大眼的彩色海洋角色，透明玻璃质感的鱼缸和气泡，安静一些的海底场景；界面是**平面纯色**——白色的容器配深蓝字，凸起的部件（按钮、标题牌、蓝色的块）只在下面压一道同色系的粗边，没有渐变、高光和描边。整体明亮、干净、可爱。（2026-11-16 之前是亮面果冻风：每个部件都有深色描边、亮边、厚度和高光，观感以 `art/ui-final/` 的定版图为准；用户说「太厚重、老套」，改成现在这样。定版图现在只当版面的历史参考。）

被否决过的方向：大圆角胶囊按钮（用户不喜欢）、代码画的扁平厚果冻（太简单）、白色实心卡片配蓝字（像办公软件，挡住场景）、轻玻璃半透明（花背景上看不清）、糖果粗描边套框（边框套边框）。 2026-11-16 起又否决：亮面果冻风（厚重）、整条深色底栏、摊成扇形的小订单卡（看不清）、任务和收藏用一行行的列表（「像网页」）。其中「白色实心卡片配蓝字」当时否掉是因为整页铺白卡挡住场景，现在的白色容器只用在弹窗、面板和信息条上，列表和卡片是蓝色的块。

| 维度 | 设定 |
|---|---|
| 原则 | **简洁**。界面是衬托，不抢插画的戏 |
| 主按钮 | 每屏只有一个带字的主按钮，放在下半屏拇指区；其余操作是不带字的圆形图标键，靠红点、数字角标提示 |
| 按钮质感 | **平面按钮**（用户 2026-11-16 定：亮面果冻按钮和后来的薄一版都「太厚重」，不要在旧图上改，重新设计）：纯色平面的圆角方块（圆角约按钮高的 24%），没有渐变、高光、描边；只在下面压一道同色系的深色粗边（约按钮高的 11%）。按钮上的字白色、不描边，下面压一道和粗边同色的实色。按下整体缩到 0.96 并压暗。程序直接画：`python3 tools/art/flat_skin.py`，颜色在脚本里；不是胶囊 |
| 平面部件（整套界面） | 用户 2026-11-16 看过三张设计稿（`art/briefs/redesign/`）后确认方向，先做主页，2026-11-17 全部页面、弹窗、局内换完：整套界面是平面纯色。**容器一律是白的**（弹窗底板、面板、主页顶栏），不凸起，上面写深蓝字；局内顶上的两块信息条（已救几条、第几关）例外，用和技能格子同一种半透明深蓝的圆头小条（`f_hud`）配白字（用户 2026-11-17：局内顶上的白色卡片显得廉价）；容器里的格子（设置行、签到格）是浅蓝。**凸起的部件**只压一道同色系的下边：按钮、蓝色的标题牌和标签牌、蓝色的块（商品卡、任务卡、册子卡）、金色的块（今天能领的那一格）、图标键。半透明白格子垫在主页入口、局内技能键、暂存格后面。彩色部件上的字白色不描边，下面压一道深色；直接压在场景上的字才用白字深蓝描边。键上、按钮上的图标是平面的白色图标（返回、叉、加号、齿轮、摄像机、分享、音符、喇叭、震动、地球、秒表、小鱼），放进白色容器里时染成蓝色。底栏先后试过深蓝整条、白色托盘，用户都不满意，直接去掉（`docs/01` 5.3）。部件都由 `tools/art/flat_skin.py` 程序画，文件名 `f_*`（按钮沿用 `j_btn_*`）。还是插画的：鱼、图标、宝箱、鱼缸、气泡和障碍、局内的目标卡、收藏册封面、连击的艺术字 |
| 圆角 | 按钮、标签条都是**圆角方块**（圆角约为高度的 24%～30%），不是胶囊；图标键是圆角方块；面板圆角 30，弹窗 42 |
| 弹窗 | 白色圆角底板，蓝色标题牌骑在上沿正中，右上角红色关闭键；内容是深蓝字；最多两个主次按钮（生命弹窗是四个一样大的选项按钮，排成两行）。按钮上的字要短：只写结果和代价（「+1」「双倍」「复活」），不写长句（用户 2026-11-16） |
| 框中框 | 禁止。按钮、卡片、资源栏都不套框 |
| 形状统一 | 同类元素只用一种形状：关卡点全是圆，入口全是圆形图标，卡片全是同尺寸圆角块 |
| 文字 | 荆南麦圆体 KN Maiyuan（OFL 许可；用户 2026-11-18 从五款候选里选定：原来的资源圆体 Resource Han Rounded 看着和系统字体差不多，没有游戏感；先选的荆南波波黑看着像加粗的普通字）。字形按比例放大到汉字高 0.93 个字号、整体上移到汉字中心对准节点中心（`font_subset.py` 的 `normalize()`），和原来的字一样大、一样居中，界面的字号不用改。白字加深色描边（约字号的 1/18；用户 2026-11-16：原来 1/12 配最粗一档的字，看着太粗太重）和一道比描边更深的硬投影（约字号的 1/26，做出一点厚度）；浅色面板上才用深蓝字不描边。字要大：主页「开始」66，其余主按钮 56～64、标签与页签 34～36、顶栏数字 38、正文不小于 28（750 宽设计稿像素）。说明文字尽量删，一个按钮最多 4 个字。**汉字和单词一律摆正：不倾斜、不旋转、不用斜体**；只有纯数字允许 ±4° 以内的轻微倾斜。**按钮上的字按 2 倍渲染再缩回去**（引擎按 750 宽的设计尺寸画字，高分屏上放大会糊，用户 2026-11-16 指出「开始」发糊）。**数字不加千分位逗号**（用户 2026-11-16 定：100449 就写 100449） |
| 字不出框 | 字不许比它的底板宽、不许压到旁边的东西（用户 2026-11-16：英文下标题、按钮、标签条到处出框）。`kit.ts` 里按钮 `button()`、标签条 `capsule()` 里的字超宽自动缩小；页标题一律用 `pageTitle()`（同一块牌、同一个高度和字号，牌宽跟着字走）；一行里左右两段字用 `fitPair()`，单独一行用 `fit()`。新页面不要自己摆标题牌 |
| 色彩 | 界面主色是宝蓝（条、面板、标签）；按钮按语义固定：绿 = 主行动，蓝 = 次行动，琥珀 = 看广告与领奖励，红 = 危险与关闭，灰 = 不可用 |
| 角色 | 团子比例（头身 1:1）、大眼睛带高光点、无牙无刺 |

参考色：宝蓝 `#1E6BF0`（亮边 `#3FD8FF`、描边 `#0B2A73`）、行动绿 `#3DD12A`（描边 `#1E6B12`）、琥珀 `#FFB01F`、红 `#F0503C`、灰 `#B9C5D3`、白字描边深蓝 `#0B2A73`。

**界面部件是程序画的平面部件**（`tools/art/flat_skin.py`，见上表「平面部件」），放在 `client/assets/resources/ui/skin`。界面只能用 `client/assets/scripts/ui/kit.ts` 提供的部件，不直接画色块。

字体（见 `client/licenses/LICENSE-KNMaiyuan.txt`）只留游戏文案用到的字（约 0.25 MB，内部名字改成不带空格的 `FishGame`），放在本地 boot 包 `client/assets/boot/game.ttf`，打进微信安装包；新增文案后跑 `./run.sh font-subset`。玩家昵称里字体没有的字由系统字体逐字补上。不能放进 `resources`：微信版的 resources 从网上下，引擎对下载来的 TTF 注册失败时会静默退回 Arial，整个界面变成系统字体（2026-11-18 出过）。

稀有度配色：普通 冰蓝 · 精良 草绿 · 稀有 天蓝 · 史诗 紫 · 传说 金。

## 4. 生物设计规则

局内出场的生物和收藏卡分开管理。

### 4.1 局内生物（94 种，按海域出，辨识第一）

- **不限于鱼**：小丑鱼、河豚、海星、鲨鱼、螃蟹、章鱼、海马、水母、海龟、鳐鱼、贝壳、乌贼、龙虾、灯笼鱼、剑鱼、海豚等，轮廓各不相同。
- **硬规则：同一关里任意两种必须一眼分得清。** 颜色按图上量出来的主色算色差（`species.json` 的 `rgb`，Lab 色差），不看登记的颜色名字——名字不同的颜色可以几乎一样（橙和朱红、红和绯红、青和天蓝）；原来 16 种的 `hue` 是 16 个互不相同的标签，按标签去重永远通过，等于没去重（2026-11-16 复查指出，同日改成按色差挑）。色差的下限按关卡号定（`docs/02` 第 2.2 节）：前面的关卡差得很开，越往后越接近。轮廓类（圆 / 扁长 / 竖长 / 星形 / 横宽带钳 / 伞形 / 菱形 / 多足 / 带壳 / 尖吻）在满足色差的前提下也尽量不重复：`species.json` 的 `shape` 按这 10 类登记（`round` / `long` / `tall` / `star` / `claws` / `umbrella` / `diamond` / `legs` / `shell` / `snout`），16 种里小丑鱼、河豚、灯笼鱼同属圆，鲨鱼和海豚同属扁长，螃蟹和龙虾同属带钳，章鱼和乌贼同属多足，海龟和贝壳同属带壳，其余一类一种。现有 120 关里前 14 关同场轮廓都不重复；7 种以上的关卡颜色优先，会有 1–2 对同类轮廓。
- 一关最多同时出 10 种（轮廓类只有 10 类）。
- 验收方法：缩到 64px、再转灰度，同一海域的局内生物两两仍能一眼分清；拍一张并排的对照图给用户确认。另按后期挑战关的实际情况，在手机竖屏上截一张场上同时有 10 种生物的局内图，用户确认能一眼分清。
- 局内只从「已有美术」的生物里挑，按色差和轮廓去重（`client/assets/scripts/core/model/speciesPick.ts`）；第一版的 12 条普通鱼里颜色或体型相近的，换成新画的 16 种。
- **第二批 30 种（c31–c60，2026-11-17）**：每个海域 5 种局内普通生物，跟着海域的主题（沙滩的寄居蟹、海胆、海参、小虾、比目鱼；冰晶洞的企鹅、海豹、磷虾、圆鳍鱼、独角鲸……），清单和出图要求在 `art/briefs/creatures2/`。Codex 一个海域出一张品红底的图，附上我们自己现有生物的对照图当风格参照（不参照任何别的游戏）；`tools/art/creatures.py` 从图边泛洪抠底（粉色、半透明的生物不会被抠穿）、切成一张一只、缩到 192×192 放进 `art/source/fish/`。主色按图量：不透明、亮度 > 0.35、饱和度 > 0.25 的像素取中位数；主体是白色、银色的（这样的像素不到三成）取亮的那部分。轮廓类在原来 10 类之外加了虾形、扁片、海兔、圆盘、管花、水獭、螺、幽灵、企鹅、海豹、鲸、天使这几类。
- 统一团子比例、大眼睛高光、无牙无刺，鲨鱼也要可爱。

### 4.2 收藏卡（705 张）

- 编号：`c01–c120` 普通、`u01–u181` 精良、`r01–r108` 稀有、`e01–e60` 史诗、`l01–l02` 传说。局内 94 种同时是收藏里的普通卡；精良以上只在收藏里。
- 稀有度越高造型越特别，不要求同屏可分：精良带一件小饰品（贝壳吊坠、叶子、围巾、蝴蝶结、小帽子），稀有戴珍珠或花冠、身上一圈贴着身子的柔光，**史诗要比别的都好看**（用户 2026-11-17）：宝石和水晶、金色花丝饰品和王冠、星空或极光花纹、珠光色、发光和几颗小星光。
- 第三批（2026-11-17，`u16–u90`、`r09–r48`、`e06–e30` 共 140 张；同日为了每册张数是 3 的倍数又加了 `r49–r54`、`u91` 7 张）：清单 `art/briefs/cards3/creatures.tsv`，按海域 × 稀有度每张图出 3–6 只（`art/briefs/cards3/*.txt`），附我们自己现有的精良以上卡当风格参照；切图同第二批（`tools/art/creatures.py <原图目录> <list.json>`）。
- **第 7–12 个海域（2026-11-17，关卡加到 240 关）**：每个海域一张局内背景（`art/briefs/worlds2/sea_*.txt`，规矩同前六张：景物在两边和底部、中间空着、颜色压低，六个海域靠色系分开：暖橄榄绿、月光青蓝、炭灰带暖、海绿石色、深海军蓝、紫靛）、一本收藏册封面（`books.txt`，附前六本当参照）、39 种生物（清单 `art/briefs/worlds2/roster.txt`：普通 10 种里 8 种在局内出场、各占一种颜色，精良 15、稀有 9、史诗 5）。一共 54 张图，`art/raw/worlds2/gen.sh` 8 个一批并行出，`tools/art/worlds2.py` 切封面、背景和生物（切生物时挨着框边、比主体小得多的碎块当作邻居去掉）。眼睛自动找不到的 6 只（深色身子）在 `eyes.py` 里手量。

## 5. Codex 出图流程

```
art/
  briefs/     # Claude 写的出图需求，一个资源一份 .md
  style/      # 风格锚定图：用户验收通过的样张，后续出图都以它们为参照
  raw/        # Codex 原始产出，不进包
  approved/   # 用户确认可用的图
tools/art/    # 裁边、压缩、打图集脚本
```

步骤：

1. **风格锚定**（只做一次）：Claude 按第 2 节写 brief，Codex 出 3 套风格样张（各含 3 条鱼 + 1 个鱼缸 + 1 个气泡 + 1 个按钮）。用户选定一套，存入 `art/style/`，之后所有出图都附带这套图做风格参照。
2. **批量出图**：Claude 写 brief → Codex 出图到 `art/raw/` → Claude 检查规格（尺寸、透明底、朝向、辨识度）→ 不合格附原因重出。
3. **验收**：按批次给用户看拼图总览，通过的移入 `art/approved/`。
4. **进包**：`tools/art/pack.py` 处理后放进 `assets/`。

brief 模板：

```markdown
# fish_c01 橘团子
- 用途：局内鱼 192×192 透明底，朝左
- 主色相：橙；轮廓类：圆（按第 4.1 节的 12 档色相、10 类轮廓）
- 造型：圆团子身体，短扇形尾，头顶一撮翘起的小鳍
- 风格参照：art/style/anchor_01.png（只参照质感与比例）
- 禁止：文字、水印、背景、阴影落地、写实纹理
```

### 调用方式（2026-11-15 验证）

```bash
cd art/raw/<批次目录>
codex exec --skip-git-repo-check --sandbox workspace-write "<英文出图描述>. Use your image generation tool. Reply with only the saved file path."
```

- Codex 的图不会落在当前目录，而是存到 `~/.codex/generated_images/<会话 id>/*.png`，路径在输出的最后一行，需要自己拷回 `art/raw/`。
- 一次调用出一张图（1024×1536 左右），约 4 分钟；多张图并行跑多个进程。
- 出图描述用英文，并写明「不得出现文字、不参照任何现有游戏」。
- `art/` 不进包；进包的图要经上面的流程放进 `client/assets/resources/`。

### 切片

Codex 出的是白底图集，用 `tools/art/slice.py` 抠成透明底并按阅读顺序切成单张：

```bash
python3 tools/art/slice.py art/raw/batch1/fish1.png art/source/fish 192 c01,c04,c05,...
```

出图描述里要写明「纯白背景、无落地阴影、元素互不接触」，否则切不开。首批资源的清单见 `art/briefs/batch1.md`。

### 界面动画约定

| 场景 | 动画 |
|---|---|
| 进关卡 | 鱼缸、暂存格、气泡、道具键依次弹出 |
| 待机 | 气泡上下漂浮、鱼摆尾、加号呼吸缩放 |
| 待机（鱼） | 除了摆尾，每条鱼还在气泡里慢慢游一小圈 |
| 点鱼、入缸、满缸、连击、结算 | 以 `docs/01` 第 3 节为准，那里是验收标准 |
| 新气泡落下 | 从屏幕上方落入、落地轻弹、挤开周围气泡 |
| 障碍 | 锁和冰块脱落；点不能点的气泡会晃动；迷雾每破一个别的气泡淡一层，显形时雾散开、问号翻成鱼；冰晶连线在依赖的气泡破掉时从那头碎掉 |
| 失败 | 整屏晃动；弹窗统一弹出式 |
| 界面 | 按钮按下缩小回弹，页签切换滑入，数值滚动 |

实现集中在 `client/assets/scripts/ui/fx.ts`，新界面复用这些函数，不各写各的。

### 界面部件

**界面部件（`client/assets/resources/ui/skin`）**：

1. 平面部件（`f_*`、`j_btn_*`）：`python3 tools/art/flat_skin.py` 直接画，形状、颜色、圆角、下边的粗细都在脚本里；横条是**横向三宫格**（按高度缩放，圆角跟着高度走），块是九宫格（圆角、下边粗细固定，又矮又小的用 `_s` 小圆角那一张）；边距写进 `client/tools/art/slices_skin.json`。
2. 还在用的插画（`j_*`）：Codex 出母版（提示词在 `art/briefs/ui_skin/`、`art/briefs/redesign/`，母版在 `art/raw/`，不进仓库），`python3 tools/art/skin.py` 和 `tools/art/obstacles.py` 切图。现有：鱼缸 `j_bowl`（白底玻璃按「越白越透」还原透明度）、气泡 `j_bubble`（黑底出图，按亮度还原透明度）、目标卡 `j_goal`、收藏册封面 `j_book_*`、排行奖牌 `j_medal_*`、教学手指 `j_finger`、挑战旗 `j_flag`、锁链 `j_chain`、迷雾和冰晶 `j_fog` / `j_mystery` / `j_ice_bead` / `j_frost`；连击艺术字：夸奖词 `j_praise_1..4`、数字 `j_dg_0..9`、`j_dg_x`、「连击」`j_combo_word`，爆炸星 `j_burst`（艺术字带中文，只在中文下用，其它语言退回普通字）。宝箱两对（关 / 开，放在 `ui/icon`）：抽奖页的紫色宝箱 `chest_wheel(_open)`、过关和各处奖励用的蓝贝壳宝箱 `chest(_open)`；一对里两张同一缩放、箱底对齐，换图时箱子不跳。
3. `./run.sh meta` 补 `.meta`。
4. 代码里用 `ui/kit.ts`：页面写部件名（`kit/panel_glass` 白色容器、`kit/row` 浅蓝格子、`kit/panel_blue` / `kit/row_blue` 蓝色块、`kit/cell_gold` 金色块、`kit/capsule` 白色小条、`kit/title_plate` 标题牌……），`slice()` 按别名表换成对应的图；按钮用 `button()`，图标键用 `keyButton()`，子页面的页头用 `shell.ts` 的 `pageHead()`。

**代码画的小件（`client/assets/resources/ui/kit`）**：由 `client/tools/art/kit.mjs` 用 SVG 写出，只剩特效用的光、环、星、彩纸，纯色块和分隔线。

### 弹窗

所有弹窗（暂停、设置、生命、开缸位、复活、离开确认、功能解锁）共用一套：

- 一层实色深海蓝面板，圆角 18，不透明；**里面不再套浅色内框**。
- 标题压在面板顶部一条亮蓝色带上，白字摆正。
- 右上角红色圆形关闭键，略微探出面板。
- 图标直接放在面板上，说明文字用白字，数值用金黄。
- 按钮最多两个：主按钮绿色在右，次按钮蓝或橙在左；看广告的按钮右上角带小视频角标，金币价按钮左侧带金币图标。
- 出现时缩放回弹约 0.2 秒，背景压暗 60%；点背景不关闭带代价的弹窗。

### 清晰度要求

- 抠图用 `tools/art/slice.py`：按白底混入比例还原半透明边缘并去掉白色成分，不允许用硬阈值切边。
- 所有贴图的 `.meta` 都开 mipmap、线性过滤（`./run.sh meta` 生成），缩小显示才不会有锯齿。
- 贴图源尺寸至少是最大显示尺寸的 1.5 倍；背景用 1024×1536 原图。
