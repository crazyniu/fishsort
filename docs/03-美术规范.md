# 03 美术规范

## 1. 原则：同品类观感，原创设计

参考截图只用来确定**品类气质**：明亮、圆润、高饱和的卡通海洋休闲风，粗描边大字，厚实的立体按钮。

除此之外全部原创，以下内容**不得**出现：

- 照着参考截图画的鱼、鱼缸、木架、头像、道具图标、场景插画、标题字。
- 参考游戏的鱼名、场景名、界面逐像素布局。
- 把参考截图作为图生图的输入喂给 Codex。

原因不只是规矩：微信、抖音、Google Play 都会因美术雷同下架并可能封号，软著和商标也过不了。

## 2. 本作的视觉识别

一句话：高饱和蓝绿色海底场景，圆润大眼的彩色海洋角色，透明玻璃质感的鱼缸和气泡；界面是**亮面果冻风**——饱和的宝蓝条和面板、亮绿主按钮，每个部件都有深色描边、顶部一道亮边、下沿一圈厚度和一点高光；白色大字加深色粗描边和投影。整体明亮、可爱、有玩具质感，观感以 `art/ui-final/` 的定版图为准。（用户 2026-11-16 定：界面按定版图的质感重做，一页一页验收；**按钮不用大圆角胶囊**，用圆角方块。）

被否决过的方向：大圆角胶囊按钮（用户不喜欢）、代码画的扁平厚果冻（太简单）、白色实心卡片配蓝字（像办公软件，挡住场景）、轻玻璃半透明（花背景上看不清）、糖果粗描边套框（边框套边框）。

| 维度 | 设定 |
|---|---|
| 原则 | **简洁**。界面是衬托，不抢插画的戏 |
| 主按钮 | 每屏只有一个带字的主按钮，放在下半屏拇指区；其余操作是不带字的圆形图标键，靠红点、数字角标提示 |
| 按钮质感 | 轻一版的亮面按钮（用户 2026-11-16：原来的厚果冻按钮「太厚重、老套」）：上浅下深的柔和渐变、同色系的细描边、下沿只有一道薄厚度（约按钮高的 6%）、上三分之一一条很淡的高光带；不要硬的白色高光点和内描边。按下整体缩到 0.96 并压暗。母版 `art/raw/ui_skin/btn.png`，出图描述 `art/briefs/ui_skin/btn.txt` |
| 圆角 | 按钮、标签条、顶栏都是**圆角方块**（圆角约为高度的 28%～35%），不是胶囊；图标键是圆角方块；面板与弹窗 32 |
| 弹窗 | 主色厚框（框内下沿同样有深色厚度）+ 奶油色 `#FFF6E3` 内容区；最多两个按钮；关闭是右上角红色圆键 |
| 框中框 | 禁止。按钮、卡片、资源栏都不套框 |
| 形状统一 | 同类元素只用一种形状：关卡点全是圆，入口全是圆形图标，卡片全是同尺寸圆角块 |
| 文字 | 资源圆体 Resource Han Rounded CN **Bold**（OFL 许可；用户 2026-11-16：原来用最粗的 Heavy，看着太粗太重，换细一档）。白字加深色描边（约字号的 1/18；用户 2026-11-16：原来 1/12 配最粗一档的字，看着太粗太重）和一道比描边更深的硬投影（约字号的 1/26，做出一点厚度）；浅色面板上才用深蓝字不描边。字要大：主页「开始」中文用艺术字图（高 90）、其它语言字号 80，其余主按钮 56～64、标签与页签 34～36、顶栏数字 38、正文不小于 28（750 宽设计稿像素）。说明文字尽量删，一个按钮最多 4 个字。**汉字和单词一律摆正：不倾斜、不旋转、不用斜体**；只有纯数字允许 ±4° 以内的轻微倾斜。**按钮上的字按 2 倍渲染再缩回去**（引擎按 750 宽的设计尺寸画字，高分屏上放大会糊，用户 2026-11-16 指出「开始」发糊）。**数字不加千分位逗号**（用户 2026-11-16 定：100449 就写 100449） |
| 字不出框 | 字不许比它的底板宽、不许压到旁边的东西（用户 2026-11-16：英文下标题、按钮、标签条到处出框）。`kit.ts` 里按钮 `button()`、标签条 `capsule()` 里的字超宽自动缩小；页标题一律用 `pageTitle()`（同一块牌、同一个高度和字号，牌宽跟着字走）；一行里左右两段字用 `fitPair()`，单独一行用 `fit()`。新页面不要自己摆标题牌 |
| 色彩 | 界面主色是宝蓝（条、面板、标签）；按钮按语义固定：绿 = 主行动，蓝 = 次行动，琥珀 = 看广告与领奖励，红 = 危险与关闭，灰 = 不可用 |
| 角色 | 团子比例（头身 1:1）、大眼睛带高光点、无牙无刺 |

参考色：宝蓝 `#1E6BF0`（亮边 `#3FD8FF`、描边 `#0B2A73`）、行动绿 `#3DD12A`（描边 `#1E6B12`）、琥珀 `#FFB01F`、红 `#F0503C`、灰 `#B9C5D3`、白字描边深蓝 `#0B2A73`。

**界面部件由 Codex 出母版位图**（按钮、顶栏、底栏、标签条、图标键、头像框），放在 `client/assets/resources/ui/skin`，流程见第 5 节「界面部件」。只有纯几何的小件（进度条槽、压暗层、渐隐带、数字凹槽）用代码画。界面只能用 `client/assets/scripts/ui/kit.ts` 提供的部件，不直接画色块。

字体已裁剪到常用字（约 2.8 MB，见 `assets/fonts/LICENSE-ResourceHanRounded.txt`），上小游戏前再按实际用字裁一次。

稀有度配色：普通 冰蓝 · 精良 草绿 · 稀有 天蓝 · 史诗 紫 · 传说 金。

## 4. 生物设计规则

局内出场的生物和收藏卡分开管理。

### 4.1 局内生物（16 种，辨识第一）

- **不限于鱼**：小丑鱼、河豚、海星、鲨鱼、螃蟹、章鱼、海马、水母、海龟、鳐鱼、贝壳、乌贼、龙虾、灯笼鱼、剑鱼、海豚等，轮廓各不相同。
- **硬规则：同一关里任意两种必须一眼分得清。** 颜色按图上量出来的主色算色差（`species.json` 的 `rgb`，Lab 色差），不看登记的颜色名字——名字不同的颜色可以几乎一样（橙和朱红、红和绯红、青和天蓝）；`species.json` 里 16 种的 `hue` 是 16 个互不相同的标签，按标签去重永远通过，等于没去重（2026-11-16 复查指出，同日改成按色差挑）。色差的下限按关卡号定（`docs/02` 第 2.2 节）：前面的关卡差得很开，越往后越接近。轮廓类（圆 / 扁长 / 竖长 / 星形 / 横宽带钳 / 伞形 / 菱形 / 多足 / 带壳 / 尖吻）在满足色差的前提下也尽量不重复：`species.json` 的 `shape` 按这 10 类登记（`round` / `long` / `tall` / `star` / `claws` / `umbrella` / `diamond` / `legs` / `shell` / `snout`），16 种里小丑鱼、河豚、灯笼鱼同属圆，鲨鱼和海豚同属扁长，螃蟹和龙虾同属带钳，章鱼和乌贼同属多足，海龟和贝壳同属带壳，其余一类一种。现有 120 关里前 14 关同场轮廓都不重复；7 种以上的关卡颜色优先，会有 1–2 对同类轮廓。
- 一关最多同时出 10 种（轮廓类只有 10 类）。
- 验收方法：缩到 64px、再转灰度，16 种两两仍能一眼分清；拍一张 16 种并排的对照图给用户确认。另按后期挑战关的实际情况，在手机竖屏上截一张场上同时有 10 种生物的局内图，用户确认能一眼分清。
- 局内只从「已有美术」的生物里挑，按色差和轮廓去重（`client/assets/scripts/core/model/speciesPick.ts`）；第一版的 12 条普通鱼里颜色或体型相近的，换成新画的 16 种。
- 统一团子比例、大眼睛高光、无牙无刺，鲨鱼也要可爱。

### 4.2 收藏卡（60 张）

- 编号：`c01–c30` 普通、`u01–u15` 精良、`r01–r08` 稀有、`e01–e05` 史诗、`l01–l02` 传说。局内 16 种同时是收藏里的普通卡。
- 稀有度越高造型越特别（发光、头饰、稀奇物种），不要求同屏可分。
- 命名原创，两到三个字，口语可爱，如「橘团子」「薄荷卷」「雪顶」。清单由 Claude 写入 `species.json`，用户过目后再开画。

## 5. Codex 出图流程

```
art/
  briefs/     # Claude 写的出图需求，一个资源一份 .md
  style/      # 风格锚定图：用户验收通过的样张，后续出图都以它们为参照
  raw/        # Codex 原始产出，不进包
  approved/   # 用户确认可用的图
tools/art/    # 裁边、压缩、打图集脚本
```

步骤：

1. **风格锚定**（只做一次）：Claude 按第 2 节写 brief，Codex 出 3 套风格样张（各含 3 条鱼 + 1 个鱼缸 + 1 个气泡 + 1 个按钮）。用户选定一套，存入 `art/style/`，之后所有出图都附带这套图做风格参照。
2. **批量出图**：Claude 写 brief → Codex 出图到 `art/raw/` → Claude 检查规格（尺寸、透明底、朝向、辨识度）→ 不合格附原因重出。
3. **验收**：按批次给用户看拼图总览，通过的移入 `art/approved/`。
4. **进包**：`tools/art/pack.py` 处理后放进 `assets/`。

brief 模板：

```markdown
# fish_c01 橘团子
- 用途：局内鱼 192×192 透明底，朝左
- 主色相：橙；轮廓类：圆（按第 4.1 节的 12 档色相、10 类轮廓）
- 造型：圆团子身体，短扇形尾，头顶一撮翘起的小鳍
- 风格参照：art/style/anchor_01.png（只参照质感与比例）
- 禁止：文字、水印、背景、阴影落地、写实纹理
```

### 调用方式（2026-11-15 验证）

```bash
cd art/raw/<批次目录>
codex exec --skip-git-repo-check --sandbox workspace-write "<英文出图描述>. Use your image generation tool. Reply with only the saved file path."
```

- Codex 的图不会落在当前目录，而是存到 `~/.codex/generated_images/<会话 id>/*.png`，路径在输出的最后一行，需要自己拷回 `art/raw/`。
- 一次调用出一张图（1024×1536 左右），约 4 分钟；多张图并行跑多个进程。
- 出图描述用英文，并写明「不得出现文字、不参照任何现有游戏」。
- `art/` 不进包；进包的图要经上面的流程放进 `client/assets/resources/`。

### 界面部件

**位图部件（`client/assets/resources/ui/skin`，新界面都用这套）**：

1. Codex 按定版图的材质出母版：白底、正视、无文字无图标、中间一段左右完全均匀，一张图只放一到三个部件（分辨率才够）。参考图用从定版图上裁下来的局部，提示词写明「圆角方块，不是胶囊」。提示词存在 `art/briefs/ui_skin/`，母版存在 `art/raw/ui_skin/`（不进仓库）。
2. `python3 tools/art/skin.py` 切图：抠透明底；横条压成**横向三宫格**（留两头，中间一条，接缝向中间色过渡）；一张母版按色相转成整套语义色（绿色按钮母版 → 蓝、琥珀、红、灰），所以各色按钮形状和高光完全一致；边距写进 `client/tools/art/slices_skin.json`。
3. `./run.sh meta` 补 `.meta`。这套图不做调色板量化（渐变会出色带），体积靠分包解决。
4. 代码里用 `ui/kit.ts` 的 `plate()`：整张按高度等比缩放，只有中间横向拉伸，圆角、描边、高光不变形；按钮用 `button()`，图标键用 `keyButton()`。

### 弹窗

所有弹窗（暂停、设置、生命、开缸位、复活、离开确认、功能解锁）共用一套：

- 一层实色深海蓝面板，圆角 18，不透明；**里面不再套浅色内框**。
- 标题压在面板顶部一条亮蓝色带上，白字摆正。
- 右上角红色圆形关闭键，略微探出面板。
- 图标直接放在面板上，说明文字用白字，数值用金黄。
- 按钮最多两个：主按钮绿色在右，次按钮蓝或橙在左；看广告的按钮右上角带小视频角标，金币价按钮左侧带金币图标。
- 出现时缩放回弹约 0.2 秒，背景压暗 60%；点背景不关闭带代价的弹窗。

### 清晰度要求

- 抠图用 `tools/art/slice.py`：按白底混入比例还原半透明边缘并去掉白色成分，不允许用硬阈值切边。
- 所有贴图的 `.meta` 都开 mipmap、线性过滤（`./run.sh meta` 生成），缩小显示才不会有锯齿。
- 贴图源尺寸至少是最大显示尺寸的 1.5 倍；背景用 1024×1536 原图。
