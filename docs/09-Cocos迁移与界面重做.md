## 3. 通用视觉规范（从定版图提炼）

- **画风**：明亮水下场景，果冻质感、厚描边、高光；主色宝蓝 + 青蓝，主按钮绿，次按钮蓝，强调金黄，警示红。
- **弹窗**：宝蓝圆角厚框 + 浅青内底（`16`、`18`）或整块宝蓝底（`15`、`19`）；标题在顶部胶囊里；右上圆形关闭键；角落可点缀珊瑚、小鱼。背景压暗。
- **按钮**：胶囊形，上半高光、下沿深色厚边；绿 = 主行动，蓝 = 次行动，金黄 = 广告翻倍类，灰 = 禁用。广告按钮前面带「视频」图标，花金币的按钮前面带金币图标并写数字。
- **胶囊信息条**：深蓝半透明胶囊，左侧图标 + 白色数字（顶栏、家园的星星 / 区域 / 金币、局内的进度和关卡号）。
- **页面标题**：页面顶部居中一块白字深蓝描边的大字，下垫云朵状或胶囊状底板（`04`、`05`、`06`）。
- **底栏**：整条宝蓝圆角底板，5 格，选中格是凸起的浅蓝方块、图标更大；页签之间细分隔线；红点在图标右上角。
- **文字**：白字 + 深蓝描边 + 轻投影；汉字不倾斜（`docs/01` 第 0 节）。
- **背景**：每个页面都铺满水下场景（光束、气泡、珊瑚、沙地），弹窗下面是压暗后的场景，不是纯色。

## 6. 动画要求

规则：`docs/01` 第 0 节第 4 条「爽」、第 3 节全部照做；以下是本次特别点名的，**都要有**：

- **主页**：鱼群常驻游动——每条鱼各自上下浮动、身体轻摆（尾巴感），隔几秒有一条换位置游一小段；气泡从下往上冒；光束缓慢明暗；「开始」按钮呼吸；有红点的入口轻晃。进场：入口和按钮依次弹出，总时长 ≤ 0.8 秒。
- **抽奖**：宝箱左右晃动并越晃越大 → 盖子弹开、光芒和星星冒出 → 弹出开奖。十连：开箱后奖品一个个飞进格子，收藏卡在格子里翻面，稀有以上额外全屏翻一次。
- **新收藏卡**：卡背朝上弹出 → 翻面 → 正面 + 稀有度光圈；史诗、传说加金光、火花、彩纸和全屏闪；卡翻完才能点击继续。
- **结算**：横幅砸下 → 三颗星依次点亮 → 金币数字滚动 → 宝箱晃动、弹开亮出奖品 → 按钮出现，「下一关」呼吸；点任意处跳到最终状态；全程 ≤ 3 秒。
- **局内**：`docs/01` 3.1 表格和 3.2 连击的每一项（点鱼回弹、弧线飞行带尾迹、入缸水花、满缸爆光、新缸落下、夸奖词、连击换色和边缘发光、技能演出……）。
- **通用**：弹窗缩放回弹出现、背景压暗；按钮按下缩 0.95 松手回弹；金币飞向余额并滚动；红点脉动；页签切换时选中块滑动；领取后对应红点消失。
- 动画不挡操作（局内逻辑立即结算，表现追帧）。

## 7. 美术制作：不许有锯齿

用户要求：**能自己画就自己画，不要拿界面控件（纯色块、程序画的圆角矩形）拼图；图片不能有锯齿。**

去锯齿的硬规则：

1. 源图至少是最大显示尺寸的 2 倍（背景用 1024×1536 以上原图）；缩小用 Lanczos，在线性空间里做。
2. 不用硬阈值切边；透明边要有半透明过渡。界面部件不用 pngquant 之类的有损量化（或质量 ≥ 90 且逐张目检）。
3. Cocos 导入设置：过滤 `linear`（缩小显示的图开 mipmap、用 `linear-mipmap-linear`），**开启预乘 Alpha**（去掉透明边的黑圈），图集打包留 ≥ 2px 间距并外扩边缘。
4. 开启 WebGL 抗锯齿；高分屏按设备像素渲染，不能整屏低分辨率再放大。
5. 文字用 TTF 字体（`assets/fonts` 现有子集字体）+ Label 描边 / 阴影，不把文字画进图里（多语言要换字）。
6. 每批图出来先拼一张总览，放大到 200% 检查边缘，再给用户看。

## 8. 技术方案

- **引擎**：Cocos Creator **3.8.8**（Mac 已装，`/Applications/Cocos/Creator/3.8.8/`），TypeScript 严格模式。设计分辨率 750×1334，竖屏，适配宽度；750×1624 等长屏不挤不空。
- **工程位置**：Cocos 工程放在仓库的 `client/` 子目录（Cocos 的 `assets/` 和 Godot 的 `assets/` 不能共处一个根）。迁移验收前 Godot 代码保留不动，验收通过后在同一分支删掉 Godot 部分，再整体合并。
- **分层照旧**（`CLAUDE.md` 硬性约束 3、4、5、6 继续有效）：
  - `client/assets/scripts/core/`：从 `src/core/` 逐文件移植的纯逻辑，**不 import `cc`**，不碰时间、存储、全局随机。
  - `services/`（配置、存档、音频、广告、平台）、`ui/`、`game/`、`platform/`（`wx` / `tt` / `FBInstant` / 原生调用只许出现在这里，按能力分支）。
  - 配置和关卡继续是 JSON，迁到 `client/assets/resources/config/`，作为唯一一份；`tools/` 的脚本改读这里。
  - 文案继续走 key：`i18n/strings.csv` 移植成 Cocos 能读的格式（`zh_CN`、`en`），代码里不写死中文。
- **界面用代码搭**：和现在一样由 TS 代码生成节点（一个启动场景 + 根组件），不依赖编辑器里手拖的 prefab，便于在 Linux 上写、在 Mac 上构建。资源一律按路径用 `resources.load` 取。
- **`.meta` 文件**：资源的 `.meta` 由 Linux 上的脚本按固定规则生成（UUID 由路径算出、稳定），和资源一起提交；Mac 上构建时如果 Cocos 改写了 `.meta`，先 `git checkout --` 还原再拉代码，不在 Mac 上提交。
- **一致性保证（玩法不能变）**：
  1. 先移植 `rng`，必须与 Godot 版逐位一致。
  2. 在 Godot 版上加一个导出黄金数据的脚本（`./run.sh golden`，在 Mac 上跑）：若干关卡 × 固定操作序列的事件流和终局状态、生成器输出、宝箱 / 抽奖 / 签到在固定种子下的结果。产物进仓库。
  3. TS 版单测重放黄金数据，必须全部一致。单测用 Node（`npm test`），在 Linux 上可以跑。
  4. 6 个海域等「文档已改、代码待改」的规则，先在 TS 版按文档实现，再补对应单测；这部分没有黄金数据，以文档为准。
- **存档**：结构沿用 `docs/meta-api.md`。**现在是测试开发版，不导入任何旧存档**（Godot 版的存档、金币等都不迁移，用户 2026-11-15 定）：Cocos 版存档从 `version` 1 开始；读档时版本不对或损坏就开新档，版本对就只把缺的字段补成默认值。正式上线后结构再变才写迁移函数。
- **黄金数据怎么来**：Mac 上 `./run.sh golden <临时目录>` 导出（只读配置和关卡，不写仓库），打包成 gzip + base64 打印到终端，Linux 上分段读回、校验 sha256 后存成 `client/tests/golden/*.json.gz`，由 `client/tests/golden.test.ts` 对比。Godot 版核心逻辑再改，要重新导出。
- **Linux 上检查界面层代码**：用到 `cc` 的脚本靠 `client/.cc-types/`（不进仓库）做类型检查，`./run.sh check` 有它就查、没有就跳过。`cc.d.ts` 可以从 Mac 的 Cocos 3.8.8 安装目录取，也可以直接用 npm 上官方的 `@cocos/creator-types@3.8.8`（`npm pack` 下来，取里面的 `engine/cc.d.ts`）；`cc.env.d.ts` 只要声明 `cc/env` 里的 `DEBUG` 等几个布尔常量，`cc.custom-macro.d.ts` 留空（`export {}`）。
- **踩过的坑**：Cocos 构建用的 Babel 不认 `as X | Y`（打包脚本失败，`./run.sh check` 已加检查）；它的松散模式把 `[...Map 或 Set 或迭代器]` 编成 `[].concat(...)`，结果不对，一律用 `Array.from`（`./run.sh check` 有检查）；`resources.load` 成功时回调的 `err` 是 `undefined` 不是 `null`；命令行构建偶发把资源全标成 `importer: "*"`、运行黑屏（编辑器插件重载和资源库启动抢跑），所以 `run.sh` 每次构建前清掉 `library`、`temp`，构建后查到 `importer "*"` 就还原 `.meta`、清缓存重建，最多三次。
- **关卡工具**：`./run.sh level-verify`、`level-gen` 是 TS 版，读写 `client/assets/resources/config/levels`。现有关卡是 #53 分段并行、只挑更接近目标的关拼出来的，任何一次生成都复现不了原文件，所以不做逐字节对比；生成器和胜率已由黄金数据证明一致。
- **平台**：`PlatformBase` 接口照搬 `docs/04` 第 5 节；本分支只做 `debug` 实现（模拟广告、假排行、本地存档），其余平台留空实现。构建验证：`web-mobile`（浏览器试玩、截图）和 `wechatgame` 能打出包即可；Android / iOS / Facebook 之后单独做。
- **调试开关**：`FISHSORT_LEVEL`、`FISHSORT_AUTOPLAY` 改为网页地址参数 `?level=65&autoplay=1`，并保留「资源加满」的试玩模式与 `real` 模式。
- **`run.sh`**：改成调用 Cocos 命令行（构建 web-mobile、起本地服务并打开浏览器、跑单测、构建微信包、关卡校验），命令名尽量保持现有的。
- **Linux / Mac 分工不变**：Linux 只写代码和跑 Node 单测、画 SVG；构建、试玩、截图在 Mac 上（`docs/05` 第 9 节），截图用 `orca computer` 取浏览器窗口。
