# 04 技术架构

引擎是 Cocos Creator。项目最早用 Godot 做（M0–M4），2026-11-15 起迁到 Cocos，2026-11-16 迁完并删掉了 Godot 工程（迁移过程与决定见 `docs/09`；旧代码在 git 历史里）。

## 1. 选型

| 项 | 选择 | 说明 |
|---|---|---|
| 引擎 | Cocos Creator 3.8.8 | 微信小游戏、Android、iOS 都是官方构建目标；Mac 上在 `/Applications/Cocos/Creator/3.8.8/` |
| 语言 | TypeScript（严格模式） | |
| 工程位置 | 仓库的 `client/` | Cocos 的 `assets/` 不能和仓库根的美术源文件目录共处一个根 |
| 构建目标 | `web-mobile`（浏览器试玩、截图）、`wechatgame` | Android（AAB，Google Play）、iOS（Xcode 工程，只能在 Mac 上打包签名）之后做 |
| 单元测试 | Node 自带测试运行器（`node --test`，用 `tsx` 跑 TS），只测 `core/` | Linux 上能跑，不需要 Cocos |
| 静态检查 | `tsc`（三份配置：核心、工具、界面层）+ `run.sh check` 里的几条 grep 检查 | 见 `docs/05` |
| 后端 | 无 | 见 CLAUDE.md |

## 2. 平台

三个平台（用户 2026-11-18 定）：微信小游戏（中国大陆）、Google Play 和 iOS（只上海外）；这一版都只靠广告，不做内购。抖音不做。一套代码、一个分支，三端各出一个包，不为某个平台拆分支或复制工程。

Cocos 的 `wechatgame` 构建直接产出小游戏工程（`client/build/wechatgame`），不需要自己写适配层。三个平台的实现都在 `platform/` 里（2026-11-18 做了微信和原生；排行榜、云存档还没做），打包和做新游戏的流程见 `docs/10`。微信打包与包体（主包 ≤ 4 MB、分包）用户 2026-11-16 定为先不管，见第 8 节现状。

依赖方向（只能向下）：`pages / game → ui → services → core`；`services → platform`。`core` 不依赖任何人，`platform` 不碰界面（模拟广告页由 `Boot` 注入，`ui/mockAd.ts`）。

界面结构：`ui/shell.ts` 的 `Shell` 管所有页面和返回历史。没有底栏（2026-11-16 去掉）：`home` 是根页面，别的页面（商店、收藏、任务、选关、抽奖、每日挑战、局内、结算、锁页、广告测试）都是从它点进去的子页面，`go()` 时把来的那一页记进历史，`back()` 照着历史往回走，回到主页历史清空；要去的页面已经在历史里（局内 → 结算 → 下一关）就退回到那一层，历史不会越走越长。按关开放的页面（收藏、任务）没开放时 `go()` 自动换成锁页。顶栏按需显示：页面类里 `topBar = true` 的才有（只有主页）；子页面的页头统一用 `shell.ts` 的 `pageHead()`（返回键 + 标题牌，可选一条金币数）。弹窗都走 `ui/popup.ts` 的 `openPopup`，有弹窗时局内暂停。

**`.meta` 文件**：资源的 `.meta` 由 Linux 上的 `./run.sh meta` 按固定规则生成（UUID 由路径算出），和资源一起提交；Mac 上构建时 Cocos 改写的 `.meta` 不提交（构建前 `git checkout -- client`）。

## 4. 核心逻辑

`core/rules/rules.ts` 是一个确定性状态机：就地修改 `GameState`，返回本次动作产生的事件序列。

```ts
export function tap(s: GameState, bubble: number, fish: number): GameEvent[];
export function tick(s: GameState, dt: number): GameEvent[];
// 另有 unlockBowl / useNet / useBlow / useShuffle / useCurrent / revive
```

- 事件类型有 `fish_to_bowl`、`fish_to_buffer`、`buffer_to_bowl`、`bubble_pop`、`bowl_done`、`bowl_in`、`bubble_drop`、`chain_tick`、`chain_open`、`ice_melt`、`net_fish`、`blow`、`shuffle`、`slot_open`、`revive`、`win`、`lose`。洋流没有自己的事件，是按顺序连点。
- 表现层只消费事件播动画，不自己推导规则。逻辑瞬时完成，动画排队追帧，连点不丢输入。
- `GameState.clone()` 供求解器分支搜索。`core/gen/constructor.ts` 是「按解构造」的核心，关卡生成和洗牌共用。
- **与 Godot 版逐位一致**（迁移时的验收标准，现在当回归测试用）：`rng`（mulberry32）、浮点（`dist32` 按 f32 算）、取整（四舍五入远离零、整除截断）都按 Godot 版实现；`client/tests/golden.test.ts` 重放 Godot 导出的黄金数据（随机数、难度曲线、生成器、360 关的机器人胜率、40 局完整对局、8000 多次局外调用），必须全部一致。黄金数据是迁移时导出的，Godot 工程删掉后不能再重新导出：改了 `core/` 的行为导致它对不上时，先确认改动是有意的，再从黄金测试里去掉对应的那一项（并在提交说明里写明）。已去掉的：2026-11-16 关卡设计复查（#61）改了难度曲线（整项不再比）、生成器叠加障碍的方式（只比不带障碍的参数）、机器人（计时、看不见迷雾：带限时或迷雾的关卡不比胜率）、迷雾计数和洗牌不拆结伴鱼（这两类对局不比事件流）；同日试玩后洋流改成只给架上的缸（对局只比到第一次用洋流之前）；这些规则改由 `rules.test.ts`、`gen.test.ts` 按文档守着。
- 关卡生成与校验：`./run.sh level-gen`、`./run.sh level-verify`，与运行时共用 `core/`。

## 5. 平台适配层

`platform/platformBase.ts` 定义接口，`platform/index.ts` 在启动时按运行环境挑一个实现：

```ts
showRewarded(placement): Promise<'done' | 'skipped' | 'unavailable'>
showInterstitial(placement): Promise<void>
showBanner(placement) / hideBanner()
adsAvailable(): boolean                 // 现在能不能播；不能时入口变灰（docs/01 7.1）
getProfile(): Promise<{ nickname, avatar } | null>
getRankList(board): Promise<RankEntry[]> // 好友周榜，不含自己（界面先隐藏，见 docs/01 5.9）
loadData(key) / saveData(key, value)
share(payload): Promise<boolean>
submitScore(board, value) / vibrate(kind) / track(event, params)
hasCapability(cap): boolean             // 'ads'（这一版有没有广告，没有就隐藏入口）| 'friend_rank' | 'share' | 'ad_test' | 'iap' …
launchQuery(): Record<string, string>   // 启动参数（网页是地址栏）
```

| 实现 | 调用方式 | 广告 | 排行榜 | 存档 |
|---|---|---|---|---|
| `wechat`（`platformWechat.ts`） | `wx` | 流量主（激励视频、插屏、横幅；广告位在 `game.json`，空着 = 没广告） | 未做（开放数据域好友榜） | 本地（`sys.localStorage`，引擎转到微信的存储）；云存储未做 |
| `native`（`platformNative.ts`） | 原生桥（Cocos `jsbBridgeWrapper`，`fs.*` 事件），Android 和 iOS 共用这一份 TS | Android：AdMob + UMP；iOS：AdMob + UMP + ATT 跟踪授权 | 未做（Play Games / Game Center） | 本地；云存档未做 |
| `debug` | 无 | 模拟广告页，可选三种结果；有没有广告跟 `game.json` 的 `ads.enabled` 走，地址栏 `?ads=1` / `?ads=0` 临时改 | 写死的假数据 | `localStorage`（键前缀 `fishsort.`） |

`debug` 实现必须始终可用：激励视频弹模拟广告页（5 秒倒计时，「看完」「中途关闭」「加载失败」），插屏 1 秒后可关，Banner 是底部色块（`docs/01` 7.2）；设置里有广告测试页入口（`hasCapability('ad_test')`）。功能差异一律通过 `hasCapability` 判断，业务代码里禁止按平台 id 分支；`wx` 等全局对象和原生桥只允许出现在 `platform/`。

**原生两端怎么共用**：`native` 实现只调一组统一的原生方法（`showRewarded`、`showInterstitial`、`submitScore`、`saveCloud` 等；以后做内购再加 `buy`、`restore`），Android（Java / Kotlin：AdMob、Play Games）和 iOS（Objective-C / Swift：AdMob、Game Center）各自实现这组方法，代码放 `client/native/` 进仓库。两端的游戏代码完全一样。

**数值差异用覆盖配置**：基础配置还是 `config/*.json`，每个平台只写和基础不同的几项（内购商品、广告频控、默认语言、有没有分享奖励），放 `config/platform/<平台>.json`，启动时合并上去（接平台时做）。

**资源分包按平台**：鱼、关卡、背景做成资源包（Asset Bundle）。微信上放分包或远程，App 全部打进安装包；加载代码三端一样，只是构建配置不同。

## 6. 存档

- 单一对象序列化为 JSON，带 `version` 字段（结构见 `docs/meta-api.md`，代码在 `core/meta/playerData.ts`）。开发阶段不迁移旧存档：版本不对或损坏就开新档，缺的字段补默认值；正式上线后每次结构变更再加迁移函数。
- 内容：进度、金币、技能、生命、收藏、救援记录、抽奖、签到、每日挑战、每日任务与本周积分、设置、广告频控计数、已看过的提示。
- 写入：关键节点（过关、消费、领奖）立即写本地。云存档接平台时做，冲突取进度更大的一份。
- 时间相关逻辑（签到、周榜、每日计数）用本地时间（`services/clock.ts`），v1.0 不防改时间。

## 7. 配置表

`client/assets/resources/config/`：`species.json`（705 种生物）、`economy.json`（金币、生命、技能、宝箱、抽奖、签到、连击、收藏、每日挑战、任务中心、功能开放关）、`ads.json`（广告位与频控）、`level_curve.json`（难度曲线与生成参数）、`game_ui.json`（局内与各页的手感、布局、动画参数）、`levels/*.json`（第 1–360 关，每关另有 `_e1`、`_e2` 两个更易的变体）。类型定义在 `core/config.ts`。

## 8. 包体与加载

现状（2026-11-17）：

- `client/assets/resources` 约 12.6 MB（不算 `.meta`）：界面图 6.9 MB（部件和局内插画 5.0 MB，其中连击艺术字和爆炸星 1.5 MB；图标 1.5 MB；页面背景 0.3 MB）、音频 1.9 MB、字体 1.5 MB、关卡与配置 1.4 MB、鱼约 10.8 MB（2026-11-18 生物加到 705 种，每张 192×192 调色板 PNG，平均 15 KB）；关卡文件约 5.9 MB（360 关 × 本体 + 两个易化变体）；海域背景 18 张约 1.9 MB。小游戏主包限 4 MB，鱼、关卡、背景接平台时要放进分包或远程资源（`docs/06`）。2026-11-17 删掉家园的场景和物件（3.6 MB）和旧的亮面部件；六张局内背景换成安静的新图后从 1.3 MB 降到 0.3 MB。
- 已做：PNG 一律量化成 256 色调色板（`./run.sh art-compress`，肉眼无差，界面图 21 MB → 4.4 MB；`./run.sh check` 会查没压的图）；背景音乐转 mp3（1.7 MB → 0.3 MB），音效仍是 wav；引擎只留用到的模块（2D、UI、遮罩、绘图、缓动、音频），微信包里引擎脚本约 1.5 MB。
- 音效来源分三类（用户 2026-11-16 试听后定）。**局内基础音**（点鱼「啵」、进缸的清脆声和水花、破泡、进暂存槽、落地、连击命中的「叮」）和**界面点击**（按钮、主页入口切页、开关）：沿用 Godot 版那一套合成音（`client/tools/audio/synth.py` 合成，中间产物不进仓库），由 `client/tools/audio/prepare.py` 挑选、变调后进包；点鱼、进缸、破泡各做三个音高略不同的版本随机播，连击命中沿五声音阶做 11 级。**有旋律的**（连击升档四档、断连、满缸、星星、金币、开箱和蓄力、功能开放、过关、失败）：`client/tools/audio/instruments.py` 用真实乐器采样（FluidR3_GM 音色库，MIT 许可，许可全文在同目录 `LICENSE-fluidr3.txt`；音色库本身不进仓库）按谱子渲染，全部在 C 大调上，和背景音乐同调。**其余拟音**（翻卡、洗牌、道具、报错）：`client/tools/audio/kenney.py` 从 Kenney 的 CC0 音效包里挑。背景音乐启动就放（设置里开着的话）：浏览器和小游戏要等玩家第一次碰屏幕才让出声，所以启动时放一次、第一次触摸时没在响再放一次。震动走 `services/audio.ts` 的 `buzz()`，受设置里的震动开关控制；平台实现在 `platform/`（浏览器调试版用 `navigator.vibrate`，只有安卓浏览器会震）。音效 wav 合计约 1.7 MB，微信打包时放分包或转 mp3。
- 气泡的重力（`game/pile.ts`）：只管画面的圆对圆模拟（基于位置的动力学），不依赖引擎的物理模块；每个气泡各自运动，有遮挡关系的一对用距离范围约束（`pile.linkMin`）连着、互不碰撞。参数在 `game_ui.json` 的 `pile`。规则层不看气泡位置。
- 下一步（`docs/09` 第 11 节）：界面部件改运行时代码绘制，不进包；位图只留鱼与少量主视觉。
- **微信版的资源放在网上**（2026-11-18，用户：包太大传不上去，别人都是先出一个加载页）。小游戏安装包（主包）最多 4 MB，而 `resources` 有几十 MB，所以整个 `resources` 包放到微信云开发的云存储：
  - 安装包里只有引擎（约 1.5 MB）、脚本、`boot` 包（加载页的背景、图标、文案，约 0.2 MB）。
  - 打包后 `tools/wechat/remote.mjs` 把 `resources` 挪到 `client/build/wechatgame-remote/remote/`，settings 里写上资源地址（`game.json` 的 `wechat.remoteUrl`）、标成远程包、不在启动前预读——由加载页自己下（`docs/ux/loading.md`），能显示进度、失败了能重试。和在 Cocos 里勾「远程包」的结果一样，只是不用改编辑器配置。微信构建开了 MD5 文件名（`md5Cache`），改过的文件换名字，手机里的旧缓存不会用错。
  - 启动时只读界面部件、图标、字体和眼前这片海域的鱼（第一次约 9 MB）；收藏册封面（`skin/j_book_*`）、别的海域的鱼、关卡文件、背景、音效用到时再读。`kit` 的 `img()` 遇到还没读的图先占位、读到再显示；进关前先把这关的鱼读好（`gameView.start`），读不到就提示网络不好、回主页。
  - 下载过的文件由引擎存在手机里（微信给小游戏的本地缓存），第二次打开不用再下。
  - iOS、Android、网页版不变：资源都在包里，同样的代码，只是读得快。

## 9. 适配

- 设计分辨率 750×1334，竖屏。手机适配宽度（`FIXED_WIDTH`），长屏时上下多出的空间由各页按 `Screen.top` / `Screen.bottom` 自己分配。**比 750:1334 还宽的屏**（平板、折叠屏展开、电脑上的微信小游戏窗口）改成适配高度（`FIXED_HEIGHT`）：高度固定 1334、宽度大于 750，各页按 `Screen.W` 左右铺开，不会因为高度不够把版面挤坏（`Boot.ts` 按屏幕比例选，2026-11-18）。
- **安全区**（用户 2026-11-18：适配刘海屏）：`ui/screen.ts` 读引擎的 `sys.getSafeAreaRect()`，顶上被刘海、灵动岛、状态栏占掉的叫 `safeTop`，底下手势条占掉的叫 `safeBottom`；`Screen.top` / `Screen.bottom` 已经扣掉它们，所有页面都按这两个排。平台还能另给安全区（`PlatformBase.safeArea()`）。
- **微信小游戏的胶囊按钮**（右上角「··· ⊙」）：平台层给出它的位置（`PlatformBase.menuButton()`，微信用 `wx.getMenuButtonBoundingClientRect()`），`Screen.applyPlatform` 把 `safeTop` 加到胶囊下沿再空 10，顶栏整体压到胶囊下面，右上角的设置键不会被盖住。
