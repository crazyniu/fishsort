# 04 技术架构

## 1. 选型

| 项 | 选择 | 说明 |
|---|---|---|
| 引擎 | Godot 4.7.x（本机已装 4.7.2） | 用户指定 |
| 语言 | GDScript，全量静态类型 | Godot 4 的 Web 导出不支持 C#，所以不用 C# |
| 渲染 | Compatibility（WebGL 2 / GLES 3） | 小游戏与低端安卓都走它 |
| Web 导出 | 单线程模板（不依赖 SharedArrayBuffer） | 小游戏环境没有跨域隔离 |
| 单元测试 | 自带的极简运行器 `tests/run_tests.gd`，只测 `src/core` | 不引入测试框架 |
| 静态检查 | gdtoolkit（`gdlint`、`gdformat`） | |
| 后端 | 无 | 见 CLAUDE.md |

## 2. 头号风险：Godot 上小游戏平台

Android 是 Godot 的官方导出目标，没有问题。**微信小游戏和抖音小游戏不是**：Godot 官方只有浏览器 Web 导出，两个平台也没有像 Unity 那样的官方转换工具。立项时查到的情况是只有社区移植方案，且公开案例多基于 Godot 3.6。

要让 Godot 4 的 Web 产物跑在小游戏里，需要自己解决：

| 问题 | 说明 |
|---|---|
| 运行环境 | 小游戏没有 DOM / `window`，要给 Godot 的 JS 启动器垫一层适配（canvas、事件、`fetch`、音频） |
| 包体 | 官方 Web 模板的 wasm 未压缩有几十 MB，远超 4 MB 主包。需要自编译裁剪模板（关 3D、物理、高级文本等）+ brotli，放进分包 |
| 文件系统 | `.pck` 的加载与持久化要改走平台文件 API |
| 音频 | Web Audio 行为与浏览器不同，可能要改走平台音频接口 |
| iOS | 微信 / 抖音在 iOS 上对 WebGL 2 和 wasm 内存的支持要真机验证 |
| 平台 API | 广告、分享、排行榜要从 GDScript 经 `JavaScriptBridge` 调到 `wx` / `tt` |

因此 **M0 的第一件事就是技术验证**（见 `docs/07`）：一个带贴图、音效、触摸的空 Godot 工程，在微信和抖音的开发者工具及安卓、iOS 真机上跑起来，并量出包体与启动时间。验证结论写回本节。

验证不过时不自行换方案，把数据交给用户决定。届时可选的路有：改用 Godot 3.6 的社区移植方案；或 Android 用 Godot、小游戏端另做。为了让第二条路代价可控，规则层（`src/core`）与关卡数据格式保持与引擎无关，关卡 JSON 可以原样复用。

## 3. 目录

```

    rules/      #   点击结算、连锁、技能、胜负判定
    meta/       #   局外逻辑：生命、结算、宝箱、抽奖、签到、技能、分享、连击、收藏、家园、每日挑战、存档结构与迁移（接口见 `docs/meta-api.md`）
    gen/        #   关卡生成
    solver/     #   求解器与机器人
    rng/
  game/         # 局内表现：气泡场、鱼缸架、暂存槽与技能栏、连击、特效、结算页
  ui/           # 主页五个页签、抽奖子页、弹窗、通用部件与动画的脚本
  services/     # autoload：存档、配置、音频、广告调度、平台选择
  platform/     # Platform 接口及各平台实现

i18n/           # 翻译 CSV（zh_CN、en）
assets/         # 进包的图片、音频、字体
addons/         # 安卓插件
export/         # 各平台的外壳与导出配置
  wechat/       #   game.js、适配层、project.config.json
  douyin/
  android/
art/  docs/  tools/  tests/
```

autoload 服务：`Platform`（平台实现）、`Config`（配置表）、`Save`（存档）、`Audio`（音效与音乐）、`Ads`（广告入口与频控）。界面结构：`App` 根节点在 `HomeScreen`（五个页签：商店 · 家园 · 主页 · 收藏 · 排行；抽奖、每日挑战是主页进去的子页面，选关从主页入口打开，都不占页签）和 `GameScreen`（局内）之间切换；界面读写数据一律经 `src/ui/home_model.gd`，它再调 `src/core/meta`；通用动画在 `src/ui/anim.gd`，弹窗在 `src/ui/popup_card.gd`，过关演出在 `src/ui/win_fx.gd`，局内特效在 `src/game/game_fx.gd`（`GameScreen` 只管布局、输入和把规则事件转给特效）。

音频全部由 `tools/audio/synth.py` 用代码合成（原创、无版权问题），重新生成即可调整音色与旋律。

依赖方向（只能向下）：`ui / game → services → core`；`services → platform`。`core` 不依赖任何人。

## 4. 核心逻辑

`src/core/rules` 是一个确定性状态机：

```gdscript
class_name Rules extends RefCounted

## 就地修改 state，返回本次动作产生的事件序列
static func apply(state: GameState, action: Dictionary) -> Array[Dictionary]
static func tap(state: GameState, bubble: int, fish: int) -> Array[Dictionary]
static func tick(state: GameState, dt: float) -> Array[Dictionary]
# 另有 unlock_bowl / use_net / use_blow / use_shuffle / use_current / revive
```

- 动作是字典 `{ a: "tap", b, k }` 等，便于录制回放；也可以直接调具体函数。
- 事件是字典 `{ t: &"fish_to_bowl", ... }`，类型有 `fish_to_bowl`、`fish_to_buffer`、`buffer_to_bowl`、`bubble_pop`、`bowl_done`、`bowl_in`、`bubble_drop`、`chain_tick`、`chain_open`、`ice_melt`、`net_fish`、`blow`、`shuffle`、`slot_open`、`revive`、`win`、`lose`。洋流没有自己的事件，是按顺序连点，发出的都是普通点击事件。
- 表现层只消费事件播动画，不自己推导规则。逻辑瞬时完成，动画排队追帧，所以连点不丢输入。
- `GameState.clone()` 供求解器分支搜索使用。
- `src/core/gen/constructor.gd` 是「按解构造」的核心：一边调 `Rules` 模拟打法一边定鱼种，关卡生成和洗牌道具共用它。
- 机器人、单元测试、回放都直接调 `Rules`。存一局只需存 `关卡 id + 种子 + 动作列表`。
- 截图用 `tools/shot.gd`；Linux 开发机不跑 Godot，截图和界面验收都在用户的 Mac 上做（`CLAUDE.md` 第 12 条）。
- 生成器与校验器是命令行工具：`godot --headless -s tools/level/gen.gd`，与运行时共用 `src/core`。

## 5. 平台适配层

`src/platform/platform_base.gd` 定义接口，`services` 里的 autoload `Platform`（`platform_service.gd`） 在启动时按运行环境挑一个实现：

```gdscript
class_name PlatformBase extends RefCounted

func id() -> StringName                      # &"wechat" / &"douyin" / &"android" / &"debug"
func init() -> void
func show_rewarded(placement: StringName) -> int   # DONE / SKIPPED / UNAVAILABLE（协程，await）
func show_interstitial(placement: StringName) -> void
func show_banner(placement: StringName) -> void
func hide_banner() -> void
func get_profile() -> Dictionary                    # { nickname, avatar }，拒绝授权时返回空
func ads_available() -> bool                        # 广告是否可用，不可用时界面降级
func get_rank_list(board: StringName) -> Array      # 排行榜条目，开发阶段是假数据
func load_data(key: String) -> String
func save_data(key: String, value: String) -> void
func share(payload: Dictionary) -> bool
func submit_score(board: StringName, value: int) -> void
func show_leaderboard(board: StringName) -> void
func vibrate(kind: int) -> void
func track(event: StringName, params: Dictionary = {}) -> void
func has_capability(cap: StringName) -> bool  # &"iap" / &"sidebar" / &"add_to_desktop" …
```

| 实现 | 调用方式 | 广告 | 排行榜 | 存档 |
|---|---|---|---|---|
| `wechat` | `JavaScriptBridge` → `wx` | 流量主 | 开放数据域好友榜 | 本地 + 微信云存储 |
| `douyin` | `JavaScriptBridge` → `tt` | 抖音小游戏广告 | 平台排行榜 | 本地 + 平台云存储 |
| `android` | Godot Android 插件 | AdMob + UMP | Play Games Services | 本地 + Play Games 云存档 |
| `debug` | 无 | 模拟广告页，可选三种结果 | 写死的假数据 | `user://` |

`debug` 实现用于编辑器内运行，必须始终可用：广告弹出模拟广告页（见 `docs/01` 第 7.2 节），头像昵称与排行榜返回写死的数据。在真实接口接入前，三端都先跑 `debug` 实现。功能差异一律通过 `has_capability` 判断，业务代码里禁止按平台 id 分支。`JavaScriptBridge`、`Engine.get_singleton()` 取安卓插件这两类调用只允许出现在 `src/platform/`。

## 6. 存档

- 单一 Dictionary 序列化为 JSON，带 `version` 字段（现为 2，结构见 `docs/meta-api.md`）；每次结构变更加一个迁移函数 `_migrate_N_to_N1`，现有 `_migrate_1_to_2`。
- 内容：进度、金币、技能、生命、收藏、家园、抽奖、签到、设置、广告频控计数。
- 写入：关键节点（过关、消费、领奖）立即写本地，节流 5 秒同步云端。冲突取进度更大的一份。
- 时间相关逻辑（签到、周榜）用本地时间，v1.0 不防改时间。

## 7. 配置表

`config/`：`species.json`（60 种生物）、`economy.json`（金币、生命、技能、宝箱、抽奖、签到、连击、功能开放关）、`ads.json`（广告位与频控）、`level_curve.json`（难度曲线与生成参数）、`game_ui.json`（局内动画与手感参数）、`ui_home.json`（主页界面布局）、`levels/*.json`（第 1–120 关，每关另有 `_e1`、`_e2` 两个更易的变体）。`ConfigService` 加载时做字段校验，校验失败在调试构建里直接断言报错。

## 8. 包体与加载

预算在 M0 技术验证后定稿，目标值：

| 部分 | 目标 |
|---|---|
| 小游戏主包（启动器 + 适配层 + 加载页） | ≤ 4 MB |
| 引擎 wasm（裁剪 + brotli，放分包） | ≤ 8 MB |
| 主 `.pck`（局内 + 前 30 关的鱼） | ≤ 5 MB |
| 追加 `.pck`：主页场景、收藏大图、后期鱼种、音频 | 各 ≤ 4 MB，进主页后后台加载 |
| Android AAB | ≤ 60 MB |

追加内容用 Godot 的资源包机制（`ProjectSettings.load_resource_pack`）按需挂载。是否需要 CDN 取决于验证后的总包体与平台分包上限。

### 8.1 资源体积现状（2026-11-15）

`assets/` 源文件合计约 9.4 MB（不含 `.import`）：

| 目录 | 大小 | 文件数 | 说明 |
|---|---|---|---|
| `audio/` | 2.41 MB | 30 | 其中 `bgm.wav` 1.69 MB、`win.wav` 0.11 MB，余下都是短音效 |
| `fish/` | 2.61 MB | 60 | 每张 36–52 KB |
| `fonts/` | 1.54 MB | 2 | 字体已裁剪（原 2.83 MB，更早的完整版 13.7 MB），见下 |
| `ui/` | 2.26 MB | 28 | 三张背景 jpg 共 0.67 MB，其余 png 各 20–100 KB |
| `kit/` | 0.55 MB | 39 | |

最大的 20 个文件：`bgm.wav` 1.69 MB、字体 1.54 MB、`bg_home.jpg` 0.30 MB、`home_scene.jpg` 0.19 MB、`bg_game.jpg` 0.18 MB、`win.wav` 0.11 MB，其后是 `tab_collection.png`、`avatar.png`、`tab_main.png`、`gift.png`、`tool_net.png`、`coin.png`、`tool_blow.png`、`tank.png`、`chest.png`、`tab_shop.png`、`lock.png`、`ice.png`、`tab_rank.png`、`bubble.png`，均在 70–105 KB。

结论：

- **没有超预算，但主 `.pck` 预算（≤ 5 MB）不能装下全部素材。** 全部资源约 9.4 MB，其中归主包的（局内 UI、前 30 关的鱼、音效、字体）约 5 MB 出头，接近上限；主页场景、收藏大图、后期鱼种、背景音乐要按第 8 节放进追加 `.pck`，每个 ≤ 4 MB 足够。
- **PNG 已经压到头：** `tools/art/pack.py --dry-run assets` 对 123 个 png 的结果是 0.0%，没有值得再处理的大图，所以本次没有改动任何 png，也就没有前后画质对比。
- **字体：** 从 2.83 MB 裁到 1.54 MB（`./run.sh font-subset`，保留游戏用字 970 个 + ASCII + 标点 + GB2312 一级 3755 字）。如需再省，可去掉 GB2312 一级字、只留游戏用字（约 0.4 MB），代价是玩家昵称里的生僻字显示成方块。
- **建议优先压缩：** ① `bgm.wav` 改成 OGG（约 150–250 KB，省 1.4 MB 以上），`win.wav` 同理；② 三张背景 jpg 如要再省，可把质量降到 80 左右（约省 0.2 MB）；③ 鱼图按需放进追加包而不是主包。
- 本节只统计源文件；导入后 `.pck` 的实际大小要在 M0 出包后量，届时更新本节。

## 9. 适配

- 基准分辨率 750×1334，拉伸模式 `canvas_items`，长宽比 `expand`。
- 顶栏与底栏用锚点贴边并避开安全区；气泡场按可用高度等比缩放。
- 验证比例：16:9、19.5:9、21:9、平板 4:3（Google Play 要求可用，两侧留背景即可）。
