# 05 开发规范

## 1. 代码（TypeScript，Cocos 版 `client/`）

- **严格模式**：`tsconfig` 开 `strict`、`noUnusedLocals`；不用 `any`，JSON 取值收窄成具体类型。
- 命名：文件与变量 `camelCase`，类与类型 `PascalCase`，常量 `UPPER_SNAKE`；页面类叫 `XxxPage`。
- `core/` 内：**不 import `cc`**；不碰时间、存储、`Math.random`。时间由调用方传入，随机数由传入的 `Rng` 提供。和 Godot 版逐位一致的写法（`Math.imul`、`dist32`、`roundi`、`idiv`、整数键用 `Map`）不要「顺手优化」掉，黄金数据测试会拦。
- 界面层（`ui/`、`game/`、`pages/`）只做表现与输入转发，不写规则判断；规则一律调 `core/`。单个文件超过 400 行就考虑拆。
- 界面全部由代码生成（`ui/kit.ts` 的 `box`、`img`、`slice`、`text`、`button`…），不用编辑器拖 prefab。点击用 `onTap`（自带按下缩放、滑动不算点）。
- 异步回调里访问节点前先查 `node.isValid`；页面重建时先停掉挂在旧节点上的缓动。
- **Cocos 构建的坑（`./run.sh check` 都有检查）**：不写 `as X | Y`（用小函数收窄）；不展开 `Map` / `Set` / 迭代器（用 `Array.from`）；`resources.load` 成功时 `err` 是 `undefined`，判断用 `if (err)`。
- 注释只写「为什么」，用中文。不提前抽象：同样的代码出现第三次再提取。

## 2. 配置与文案

- 数值全部进 `client/assets/resources/config/`，代码通过 `App.config` 读取，不写魔法数字。
- 玩家可见文字全部走 `tr('KEY')`，key 形如 `UI_HOME_START`，翻译在 `i18n/strings.csv`（`zh_CN` 与 `en` 同步维护；改完 `node client/tools/i18n.mjs` 生成 `strings.json`）。生物名也走文案（`SPECIES_<id>`）。
- 带文字的美术图（如标题字）出中英两版，或改用字体渲染。

## 3. 测试：只测值得测的

原则：测试是为了防止规则算错和关卡不可解，不是为了数量或覆盖率。

**要写**

| 范围 | 内容 |
|---|---|
| `core/rules` | 每条规则、每种障碍、每个道具各有少量用例，重点是连锁结算与胜负边界 |
| `core/gen` | 同种子输出一致；抽样种子生成的关卡能过校验 |
| 存档迁移 | 每个迁移函数一个用例 |
| 回归 | 修规则类 bug 时补一个能复现它的用例 |

**不写**

- 界面、动画、场景、`services`、`platform` 的单元测试。
  这些靠在 Mac 上实际跑和验收。
- 从 Godot 版移植过来的函数由黄金数据测试（`client/tests/golden.test.ts`）一次性覆盖，不再逐个补用例。
- 只是转发调用、读配置、取值赋值的代码的测试。
- 覆盖率指标、快照测试、端到端自动化、为了测试而加的抽象层与 mock。
- 同一逻辑的重复用例：一个行为一个用例，边界值各一个，够了。

整套单测本地运行应在 30 秒内跑完，超过就删慢的、合并重复的。

## 4. CI（GitHub Actions）：一条流水线，三分钟内

只在 **向 `main` 提 PR** 时触发，一个 job，顺序执行：

1. `./run.sh check`：`.meta` 与图片压缩检查、Cocos 构建坑的几条 grep 检查、类型检查（核心与工具；界面层要 Cocos 的类型声明，CI 上没有，只在本地查）、`core/` 的单测（含黄金数据）
2. `./run.sh level-verify`：校验包里的全部关卡（结构、可解、新机制首发、每关 400 局机器人胜率），约 1 分钟

**CI 里不做**：

- 不在每次 push 都跑；不设定时任务。
- 不做多平台导出构建矩阵、不跑真机或模拟器、不跑界面自动化。
- 不卡覆盖率。关卡校验只有结构、可解、新机制首发这几项不过才算失败；胜率偏离目标只进报告，不拦 PR。
- 不新增 job。要加检查项，先证明它拦得住真实出现过的问题，并且总时长仍在三分钟内。

发版导出（三端构建）是手动触发的独立 workflow，不属于 CI。

## 5. 项目管理（GitHub）

仓库：`crazyniu/fishsort`。

- **Milestones**：对应 `docs/07` 的 M0–M6。
- **Issues**：一件可独立验收的事一个 issue，用仓库里的模板（功能 / 缺陷 / 美术需求）。美术需求 issue 就是给 Codex 的 brief 的索引。
- **Labels**：`core` `game` `ui` `platform` `level` `art` `docs` 表示范围；`bug` `feat` `chore` 表示类型；`wechat` `douyin` `android` 表示平台；`blocked` 表示等用户或等资质。
- **Project 看板**：Todo → Doing → 待验收 → Done。「待验收」是等用户看界面或美术的状态。
- **分支与 PR**：`main` 受保护、始终可运行；功能在 `feat/简述`、修复在 `fix/简述`；一个 PR 关联一个 issue（`Closes #n`），CI 通过后 squash 合并。
- **提交信息**：`类型(范围): 说明`，类型取 `feat / fix / refactor / docs / test / chore / art / level`，说明用中文。例：`feat(core): 锁链泡结算`。
- **Releases**：每次提审打 tag `v主.次.修`，Release 说明里写三端各自的构建号。
- 规则变更的文档与代码放同一个 PR。
- 不提交：`client/library`、`client/temp`、`client/build` 等 Cocos 缓存与构建产物、`client/.cc-types/`、`art/raw/`、`art/ui-final/`、任何密钥与签名文件。资源的 `.meta` 要提交（由 `./run.sh meta` 生成）。

## 6. 性能预算（以三四年前的中低端安卓机为准）

| 指标 | 预算 |
|---|---|
| 帧率 | 局内稳定 60，最低不低于 45 |
| Draw Call | 局内 ≤ 40，其它界面 ≤ 60 |
| 冷启动到可点击 | 小游戏与 Android 的目标值在 M0 验证后定 |
| 同屏鱼 | 160 条不掉帧 |

鱼、气泡、飞行特效走对象池；鱼共用图集以合批；局内每帧的 `update` 里不做分配。

## 7. 广告与埋点

- 激励视频统一经 `ui/popups.ts` 的 `watchAd(广告位)`；插屏频控读 `ads.json`（`core/meta/meta.ts` 的 `shouldShowInterstitial`）。业务代码不直接调平台实现。
- 激励视频只有返回 `done` 才发奖；`unavailable` 时给出提示且不扣次数。
- 埋点走 `App.platform.track`；每个广告位、每关的开始 / 胜利 / 失败 / 复活 / 道具使用的埋点在接真实平台时补齐（现在只有广告看完）。

## 8. 完成标准

1. 对应文档已更新。
2. CI 通过。
3. 在编辑器里实际跑过相关流程。
4. 涉及平台能力的，在对应平台开发者工具或真机验证过；没验证的在 PR 说明里明写「未在 X 平台验证」。
5. 没有新增魔法数字、硬编码文案、跨层调用。

## 9. 开发机与测试机分工

- **Linux 开发机（Claude 所在）**：只写代码、配置、文档、关卡工具，跑 Node 的检查与单测（`./run.sh check`、`./run.sh level-verify`），画 SVG 部件，做 `git` 操作。需要 Cocos Creator 的事（构建、试玩、截图、界面验收）不在这台机器上做。
- **用户的 Mac（Orca 环境 `Mac-Image-Worker`）**：构建与试玩都在这里。仓库路径 `/Users/apple/Documents/projects/fishsort`，Cocos Creator 3.8.8 在 `/Applications/Cocos/Creator/3.8.8/`，`run.sh` 会自动找到。
- **同步只走 git**：Linux 上提交并推送分支，Mac 上 `git checkout -- client && git pull --ff-only`（Cocos 构建会改写 `.meta`，先还原）。未推送的改动 Mac 看不到，不要用拷文件或共享目录绕过。
- **协调方式**：Claude 用 `orca` CLI 驱动 Mac，不需要用户手动操作。fishsort 已登记在 Mac 的 Orca 里（2026-11-16 用 `orca repo add --environment Mac-Image-Worker --path /Users/apple/Documents/projects/fishsort` 登记），终端开在它上面；遇到 `selector_not_found` 先 `orca repo list --environment Mac-Image-Worker` 看登记还在不在：
  1. 开终端并运行命令：`orca terminal create --environment Mac-Image-Worker --worktree "path:/Users/apple/Documents/projects/fishsort" --title <名称> --command 'cd /Users/apple/Documents/projects/fishsort && git checkout -- client && git pull --ff-only && ./run.sh level 24' --json`，记下返回的 `handle`。`./run.sh` 构建网页版、起本地服务，并用**独立的 Chrome 窗口**（单独的用户目录，不碰用户自己的 Chrome）打开；试玩参数直接跟在后面：`level <N>` 进第 N 关、`auto [起] [止]` 机器人代打（过关自动下一关、输了重打，默认打到最后一关）、`page <名字>` 打开某一页、`real` 按真实存档（`./run.sh help`）。
  2. 读输出：`orca terminal read --environment Mac-Image-Worker --terminal <handle>`，看到「Ctrl+C 停止」表示已经开好。
  3. 取运行画面：`pgrep -f fishsort-chrome` 找到那个 Chrome 的 pid → `orca computer get-app-state --app pid:<N> --environment Mac-Image-Worker --max-elements 3 --json`，结果里的 `screenshot.path` 是本机可读的 PNG，`screenshot.scale` 是截图相对窗口的缩放（窗口宽约 450）。页面求值、截图、连拍用 `./run.sh cdp eval '<表达式>'`、`cdp shot`、`cdp burst`（窗口被别的窗口挡住也能截）；`./run.sh cdp logs` 读控制台，会重新加载页面。
  4. 操作界面：`orca computer click --app pid:<N> --x <X> --y <Y> --environment Mac-Image-Worker`，坐标是**窗口坐标**，等于截图上的坐标除以 `scale`；点击后再截一次图确认生效。
  5. 收尾：测完关掉自己开的终端（`orca terminal close`），结束那个 Chrome（`pkill -f fishsort-chrome`），不在用户 Mac 上留后台进程。
- **只读优先**：在 Mac 上除 `git fetch / pull / checkout` 和 `./run.sh` 命令外，不改仓库文件，不装软件，不动 `game` 等其它项目。需要改文件的事回到 Linux 上改、提交、推送。
- **验收口径**：第 8 节「在编辑器里实际跑过」指在 Mac 上跑过。PR 说明里写清楚在 Mac 上测了什么（命令、截图），没测的明写「未在 Mac 上验证」。
- **CI 不受影响**：CI 仍在 Linux 上跑第 4 节的那一条流水线，这一节只管本地开发期的验证。
